# 📘 代码说明书
## 一句话概括
这是一个“开关控制器”，用来统一管理项目中各种功能的开启或关闭（比如某个新功能要不要对用户开放），所有开关都从环境变量里读取，方便不改代码就能灵活控制。

## 📂 文件总览
| 文件 | 作用 |
|------|------|
| `workbench_generation_api/feature_flags.py` | 提供一个统一的“功能开关面板”，让程序能根据环境变量（如开发/测试/生产环境的不同配置）决定是否启用某项功能 |

## 🔍 核心函数/类说明
- **`class FeatureFlags`**：一个“功能开关管家”，负责读取和解释环境变量里的开关设置  
  - 输入：可选传入一个字典（比如测试时模拟环境变量），不传就自动用系统真实的环境变量（`os.environ`）  
  - 输出：一个能查开关状态的对象（比如 `.testpoint_filter_enabled()` 就会告诉你“测试点过滤”功能开没开）  
  - 大白话解释：就像家里电闸箱上的一个个小开关——这个类不负责干活，只负责告诉你「这个功能的闸刀现在是推上去（开启）还是拉下来（关闭）」，而且它认得多种“开”的说法（比如 `"1"`、`"true"`、`"yes"`、`"on"` 都算打开），非常贴心。

- **`def get(self, name: str, default: bool) -> bool`**：查某个具体开关的当前状态  
  - 输入：开关名（如 `"TESTPOINT_FILTER_ENABLED"`）、默认值（如果根本没设这个开关，就用这个默认值）  
  - 输出：`True`（开了）或 `False`（关了）  
  - 大白话解释：你问它：“‘测试点过滤’这个功能开了吗？” 它就去环境变量里翻找叫这个名字的纸条；如果没找到，就按你提前说好的默认值回答（比如默认开着）；如果找到了，就看纸条上写的算不算“开”（哪怕写的是 `"YES"` 或 `"1"`，它也懂！）。

- **`def testpoint_filter_enabled(self) -> bool`** 等三个方法：封装好的常用开关快捷键  
  - 输入：无（内部固定查某个环境变量名）  
  - 输出：`True`/`False`  
  - 大白话解释：不用每次都手动写 `flags.get("TESTPOINT_FILTER_ENABLED", True)`，直接调用 `.testpoint_filter_enabled()` 就行——就像遥控器上印着“音量+”“静音”按钮，比自己按一串按键方便多了。

## 🧩 调用关系与数据流转
```
程序启动 → 创建 FeatureFlags 实例（自动加载 os.environ）
         ↓
其他模块（如 API 路由、业务逻辑）→ 调用 flags.testpoint_filter_enabled()
                                 ↓
                             调用 flags.get("TESTPOINT_FILTER_ENABLED", True)
                                 ↓
                             查 os.environ 或传入的 mock 字典 → 返回 True/False
                                 ↓
业务代码根据返回值决定：执行新功能？还是走老流程？
```

## 💡 值得学习的写法
- ✅ **宽容的字符串解析**：`str(raw).strip().lower() in {"1", "true", "yes", "on"}` 这一行，让开关支持多种常见写法（大小写不敏感、带空格也不怕），极大降低运维和测试同学配错的概率。  
- ✅ **默认值兜底 + 显式命名方法**：每个功能都有独立方法（如 `scene_auto_classify_enabled`），既避免拼错环境变量名，又让代码自解释——看到方法名就知道它管啥，不用猜变量名。  
- ✅ **构造函数支持注入环境变量字典**：方便单元测试（比如传个 `{"TESTPOINT_FILTER_ENABLED": "false"}` 模拟关闭状态），不用真的改系统环境，干净又安全。

## ⚠️ 需要注意的地方
- ⚠️ **环境变量名必须全大写且严格匹配**：比如 `PAGE_OBJECT_AUTO_BIND` 写成 `page_object_auto_bind` 或 `PAGE_OBJECT_AUTOBIND` 都会失效，导致返回默认值（可能意外开启危险功能！）。  
- ⚠️ **`default` 参数容易被忽略但影响很大**：比如 `testpoint_filter_enabled` 默认是 `True`，如果上线前忘了在环境里配这个变量，功能就会悄悄开启——建议高风险功能默认设为 `False`，显式开启更安全。  
- ⚠️ **没有类型校验和报错提示**：如果环境变量值是 `"maybe"` 或 `"2024"`，它会安静地返回 `False`（因为不在认可列表里），不会警告你“这个值我不认识！”，排查配置错误时可能绕弯路。
