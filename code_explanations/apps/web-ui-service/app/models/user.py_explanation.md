# 📘 代码说明书
## 一句话概括  
这个文件定义了一个“用户”数据模型，就像给数据库里的“用户档案柜”画了一张标准设计图——告诉程序：每个用户该存哪些信息（比如名字、密码、角色等），以及这些信息该怎么存（比如名字不能重复、时间自动记录等）。

## 📂 文件总览
| 文件 | 作用 |
|------|------|
| `user.py` | 定义数据库中「用户」这张表的结构和规则（即“用户长什么样”，不负责增删改查操作） |

## 🔍 核心函数/类说明
- **`class User(Base)`**：这是一个“用户模板”，不是真正的用户，而是告诉程序：“以后所有用户数据都得按这个样子来填”。  
  - 输入：无（它不接收参数，只是被用来创建数据库表或生成用户对象）  
  - 输出：无（它本身不返回值，但用它创建的对象可以存进数据库）  
  - 大白话解释：想象你去办图书馆会员卡，工作人员给你一张《会员登记表》——表头写着“编号、姓名、密码、身份、是否有效、创建时间、更新时间”。`User` 类就是这张表的电子版模板，连“姓名不能重复”“时间自动填”这种小提示都写进去了，省得每次手动写。

## 🧩 调用关系与数据流转  
这个文件是“静态蓝图”，**自己不主动调用别人，也不被别人直接调用执行**；但它会被其他模块悄悄“引用”和“使用”：  
```
数据库迁移工具（如 Alembic） → 看 user.py → 懂了用户表长啥样 → 自动生成 SQL 建表语句  
FastAPI 接口（如 /users/create） → 创建 User() 实例 → 填入用户名/密码 → 交给数据库保存  
验证逻辑（如登录检查） → 查询 User 表 → 找 username == "张三" 的记录 → 拿出 hashed_password 对比  
```  
→ 数据流转本质是：**其他代码用 `User` 这个模板来“造”用户对象，再把对象交给数据库存起来或查出来。**

## 💡 值得学习的写法
- `server_default=func.now()` 和 `onupdate=func.now()`：让数据库自己偷偷记下“创建时间”和“最后修改时间”，不用程序员每次手动写 `datetime.now()`——就像快递单上“下单时间”和“更新物流时间”由系统自动盖章，不怕你忘记。
- `unique=True, index=True` 同时加在 `username` 上：既保证“用户名全世界唯一”（避免重名注册），又让查“张三是谁”变得飞快（数据库会建索引，像字典的拼音索引页一样快）。
- `Mapped[int]` 和 `mapped_column(...)` 是 SQLAlchemy 2.0 的新写法，更清晰地分开“字段类型”（`int`）和“存储规则”（主键、自增），像把“身份证号是18位数字”和“这张表里它是唯一编号”分两行写清楚，不易混淆。

## ⚠️ 需要注意的地方
- `hashed_password` 字段存的是加密后的密码（比如 bcrypt 加密结果），**绝不能直接存明文密码！** 如果后续代码忘了加密就往这里塞密码，整个系统就危险了——就像把家门钥匙刻在门牌上。
- `role: Mapped[str] = mapped_column(..., default="viewer")` 中的 `default="viewer"` 是 Python 层默认值，只在你用 `User()` 创建对象但没写 `role` 时生效；但如果直接 SQL 插入数据，这个默认值不会起作用（要用 `server_default` 才行）。新手容易误以为“永远是 viewer”，其实数据库里可能空着或乱填。
- `DateTime(timezone=True)` 要求数据库支持时区（如 PostgreSQL），如果用 SQLite（默认不支持），运行会报错——就像给一个没有闹钟功能的手机硬装“世界时钟”APP，装不上。
