# 📘 代码说明书
## 一句话概括  
这个文件实现了一个“智能找按钮/找元素”的小工具：当程序想点击某个界面元素（比如网页上的“提交”按钮），但发现它暂时找不到时，会自动尝试备选方案（比如换一个名字、换一个位置），直到成功找到为止，或者彻底放弃并报错。

## 📂 文件总览
| 文件 | 作用 |
|------|------|
| `self_healing.py` | 提供「自愈式选择器解析」能力——让程序在定位界面元素失败时，能自动降级使用备用方案，而不是直接崩溃 |

## 🔍 核心函数/类说明
- **`resolve_selector_with_fallback()`**：作用是“主选+备选，逐个试，谁行用谁”。  
  - 输入：  
    - `selector`：首选的定位方式（比如 `"#submit-btn"`，意思是“找 id 是 submit-btn 的元素”）；  
    - `fallback_selectors`：一串备用定位方式（比如 `["[data-test='submit']", ".btn-primary"]`）；  
    - `selector_probe`：一个“探测函数”，你给它一个定位字符串，它返回 `True` 表示“这个能用”（比如真的能找到对应元素），`False` 表示“找不到”。  
  - 输出：一个元组 `(最终选中的定位字符串, 是否用了备选)`，比如 `("#submit-btn", False)` 表示用的是首选；`("[data-test='submit']", True)` 表示退而求其次用了第一个备用。  
  - 大白话解释：就像你去奶茶店点单，先说“我要一杯杨枝甘露”，店员说“卖完了”，你就立刻说“那换成芒果百香果也行”，再不行就换“柠檬茶”……直到点成一杯，或者所有选项都试完还点不了——这时就报错：“今天真没得喝！”  

- **`SelectorResolutionError`**：作用是专门用来喊“救命！全都不行！”的错误类型。  
  - 输入：无（它是个错误类，不是函数）；  
  - 输出：无；  
  - 大白话解释：就像奶茶店最后把菜单一合，说“对不起，我们今天连柠檬茶的茶底都没了”，然后递给你一张写着“今日售罄”的小纸条——这张纸就是这个错误，告诉调用它的上层代码：“别试了，真没招了”。

## 🧩 调用关系与数据流转  
```
外部代码（比如测试脚本或自动化流程）
       ↓ 传入：首选 selector + 备选列表 + 探测函数（如 page.query_selector）
       ↓
resolve_selector_with_fallback()  
       ↓ 按顺序把每个候选 selector 交给 selector_probe 去“现场试试看”
       ↓ selector_probe 返回 True → 立刻停止尝试，返回该 selector + 是否为备选标记
       ↓ 全部返回 False → 抛出 SelectorResolutionError
       ↓
外部代码捕获这个错误，决定是重试、截图、发告警，还是直接失败
```

## 💡 值得学习的写法  
- 使用 `*` 强制关键字参数（`def resolve_selector_with_fallback(*, selector: str, ...)`）：像给函数加了个“门禁”，调用时必须写清楚每个参数叫什么（比如 `selector="xxx"`, `fallback_selectors=[...]`），避免传错顺序或漏传，对配置类函数特别友好。  
- `candidates = [selector, *(fallback_selectors or [])]`：用解包 `*[]` 巧妙合并首选和备选，既简洁又安全（`fallback_selectors` 是 `None` 也不怕）。  
- `visited: set[str] = set()` 防重复：如果备选列表里不小心写了两个一样的选择器（比如 `["#btn", "#btn"]`），它会跳过第二个，避免白忙活——像点单时服务员提醒你：“您刚点过杨枝甘露啦，要不试试别的？”  
- 返回 `(str, bool)` 二元组：不仅告诉你“用哪个”，还顺手告诉你“是不是凑合的”，方便上层做不同处理（比如日志里标红“⚠️ 本次使用备选方案”）。

## ⚠️ 需要注意的地方  
- `selector_probe` 函数必须是“纯探测”：它只负责判断“这个 selector 能不能找到元素”，**不能**有副作用（比如不能真的点击、不能修改页面、不能发网络请求）。否则每试一次就点一下按钮，后果很严重 😅。  
- `fallback_selectors` 是 `list[str] | None`，但代码里用 `fallback_selectors or []` 容错——看起来贴心，但如果有人误传 `0`、`False` 或空字符串 `""` 这类“falsy 值”，也会被当成 `None` 处理，导致备选失效（虽然概率低，但类型系统没拦住）。  
- 没有超时或重试机制：`selector_probe` 如果卡住（比如网络延迟、页面没加载完），整个函数就会卡死。实际使用时，调用方需确保 `selector_probe` 自带超时（例如用 Playwright 的 `page.query_selector("xxx", timeout=5000)`）。  
- 错误信息较简略：`"no available selector..."` 没告诉用户“到底试了哪几个、哪个失败了”，调试时可能得加日志才能看清过程。
