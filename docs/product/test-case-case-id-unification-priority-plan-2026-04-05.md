# 测试用例编号统一与实施优先级（2026-04-05）

> 文档版本：v1.0  
> 文档目标：固化测试用例统一编号口径，明确当前不一致清单与后续实施优先级。  
> 适用范围：`shared_backend`、`AI 生成`、`Workbench`、`用例中心`、`Excel 导出`

---

## 1. 决议基线

后续统一按以下口径执行：

1. 保留平台现有命名规范：`atp-web-ret-query-sm-ai-0001`
2. 不再新增第二套业务编号：`EC-ORD-CC-0001`
3. Excel 模板中的 `用例ID` 列，直接映射平台标准 `case_id`
4. 数据库自增 `id` 继续仅作为内部主键，不对外展示为业务编号

## 2. 统一源头

当前项目中，`case_id` 的统一规范源头为：

- `shared_backend/case_ids.py`
- `shared_backend/case_rules.py`

统一规则摘要：

- 编号结构：`{project}-{client}-{page}-{module}-{case_type}-{source}-{sequence}`
- 示例：`atp-web-ret-query-sm-ai-0001`
- 老格式兼容输入：允许 `TC-*`、`PROD-*` 等旧格式被 `normalize_case_id(...)` 归一化
- 对外唯一业务编号：始终为标准化后的 `case_id`

---

## 3. 当前审计结论

总体判定：`生成链基本统一，管理链尚未统一`。

### 3.1 已基本统一的部分

- `shared_backend` 已提供统一 `case_id` 生成、归一化、校验能力
- `agents/test-design-agent` 已改为按 `shared_backend` 分配 `case_id`
- `apps/web-ui-service` 的 Workbench 生成链已使用统一分配逻辑
- `apps/ai-orchestrator` 主执行支持链已使用统一分配逻辑
- `agents/script-generation-agent` 已补齐统一逻辑，不再兜底 `TC-GENERATED-001`

### 3.2 尚未统一的部分

- `apps/web-ui-service` 的用例中心主表仍以数据库整数 `id` 作为主识别链路
- 用例中心 API、前端展示、导出仍大量使用和暴露内部 `id`
- Excel 导出尚未按模板 `用例ID -> case_id` 输出
- AI 生成用例与用例中心主表尚未形成稳定回写和统一主链
- 测试、示例、文档仍保留大量旧格式编号

这意味着：

- AI 自动生成模块和测试用例管理模块当前是“半打通”
- 当前平台还不能宣称“全局统一按 `shared_backend` 执行”

## 4. 不一致清单

### 4.1 P0：必须先修的主链问题

| 编号 | 问题 | 当前现状 | 影响 | 目标状态 |
|---|---|---|---|---|
| U-001 | 用例中心主表缺 `case_id` | `test_cases` 只有整数 `id` | 无法以业务编号统一查询、展示、导出 | 主表新增 `case_id` 并建立唯一索引 |
| U-002 | 用例中心主表缺统一编码维度 | 缺 `project/client/page_code/module_code/case_type/source` | 无法稳定生成和治理多项目编号 | 增加统一元字段并与 `case_id` 对齐 |
| U-003 | 用例中心服务仍按整数 `case_id` 处理 | Service/Router 全链路仍收 `int` | AI 生成与管理中心不能共享一套主键语义 | API 主链切到字符串 `case_id` |
| U-004 | AI/Workbench 与用例中心未形成统一落库 | 生成结果多落 YAML/State，未稳定回写用例中心 | 生成资产与管理资产断裂 | 生成结果可回写或关联到统一 `case_id` 主表 |

### 4.2 P1：紧随其后的展示与导出问题

| 编号 | 问题 | 当前现状 | 影响 | 目标状态 |
|---|---|---|---|---|
| U-101 | 列表页主显示仍是 DB `id` | 前端/DTO 主要暴露 `id` | 用户看到的不是业务编号 | 列表页主显示 `case_id` |
| U-102 | 详情页标题与路由仍按整数 ID | 页面标题、面包屑、请求参数仍是数字 ID | 用例不可跨系统引用 | 详情页主展示和查询使用 `case_id` |
| U-103 | Excel/CSV/JSON 导出未按模板输出 | 导出首列仍是 `id` | 模板对接失败 | 模板 `用例ID` 输出 `case_id` |
| U-104 | Excel 模板缺失字段未补齐 | 当前导出字段与模板差距大 | 无法直接下载企业模板 | 增加模板映射层与补全字段策略 |

### 4.3 P2：一致性清理问题

| 编号 | 问题 | 当前现状 | 影响 | 目标状态 |
|---|---|---|---|---|
| U-201 | 测试中仍有大量旧 ID | `TC-*`、`tc-product-*` 仍广泛存在 | 后续重构容易被旧样例带偏 | 测试数据迁移到标准 `case_id` 或显式标注兼容输入 |
| U-202 | README/指南仍写旧规范 | 多处文档仍以 `TC-*` 为示例 | 团队认知不一致 | 所有对外文档统一展示标准 `case_id` |
| U-203 | 示例代码仍保留旧格式 | 部分 examples 仍输出旧 ID | 新人接入容易复制错误模式 | 示例全部统一到标准编号 |

## 5. 推荐实施优先级

建议按以下优先级推进，不建议跳步。

### Phase 1：字段落库与主链打通（P0）

目标：先把“统一编号”真正变成管理主数据。

包含内容：

1. 用例中心主表新增 `case_id`
2. 用例中心主表新增统一维度字段：
   - `project`
   - `client`
   - `page_code`
   - `module_code`
   - `case_type`
   - `source`
3. 旧数据回填标准 `case_id`
4. Service 层支持按 `case_id` 查、改、删、版本对比
5. 保留内部 `id` 作为关联主键，但不再对外作为业务编号

优先级：`最高`

原因：

- 这是所有 UI、导出、AI 回写统一的基础
- 不先落库，后面的“统一展示”只是表面统一

### Phase 2：API 与前端展示统一（P1）

目标：让用户看到和使用的都是同一套业务编号。

包含内容：

1. 用例列表页主显示切到 `case_id`
2. 详情页标题、面包屑、详情头部切到 `case_id`
3. 批量接口从 `ids: list[int]` 逐步过渡到 `case_ids: list[str]`
4. 搜索支持按 `case_id` 命中
5. AI 生成结果在管理端可按同一 `case_id` 查询

优先级：`高`

原因：

- 直接影响用户认知和业务使用
- 是“AI 生成模块”和“用例管理模块”统一体验的关键一步

### Phase 3：Excel 导出与模板对齐（P1）

目标：把统一编号落到企业交付物。

包含内容：

1. Excel 模板 `用例ID` 输出 `case_id`
2. 基于 [测试用例模板映射表（2026-04-05）](./test-case-template-mapping-table-2026-04-05.md) 建立导出映射层
3. 对当前缺失字段定义：
   - 真实字段
   - 派生字段
   - 默认值策略
   - 空值策略
4. 下载格式对齐你提供的模板文件

优先级：`高`

原因：

- 这是业务落地和跨团队协作的标准交付界面
- 模板导出会反向约束字段设计是否完整

### Phase 4：测试/示例/文档全面清理（P2）

目标：防止旧规范继续污染新增代码。

包含内容：

1. 测试数据从 `TC-* / PROD-* / tc-*` 迁到标准 `case_id`
2. README、PROJECT_DOCS、FEATURES_GUIDE 统一到新规范
3. 示例 YAML、示例脚本、样例输入统一替换
4. 对必须保留的兼容输入场景，显式标记“兼容输入，不是最终输出”

优先级：`中`

原因：

- 不影响主功能先落地
- 但不清理会持续制造认知和实现偏差

---

## 6. 执行顺序建议

推荐顺序如下：

1. 字段落库方案
2. 数据回填方案
3. Service/API 双写兼容方案
4. 前端列表/详情展示切换
5. Excel 导出实现
6. AI 生成与用例中心回写打通
7. 测试、示例、文档清理

---

## 7. 验收标准

完成本专项后，至少应满足以下标准：

1. 任一用例在列表页、详情页、导出文件中显示的都是同一个 `case_id`
2. Excel 模板中的 `用例ID` 列不再出现数据库整数主键
3. AI 生成、Workbench、用例中心三条链路都能对齐到同一个 `case_id`
4. 旧格式编号只允许作为兼容输入，不允许作为最终输出
5. 新增测试与文档默认只使用标准 `case_id`
