# 测试用例管理中台执行计划（按流程图落地）

版本：`v1.0`  
创建日期：`2026-04-05`  
计划周期：`2026-04-06` 至 `2026-05-31`（8 周）  
对应架构：`输入源层 -> AI 编排层 -> 测试用例管理层 -> 测试资产中心 -> 执行层 -> 结果回写 -> AI 反哺`

---

## 0. 执行目标

在不破坏现有可用能力的前提下，完成“测试用例管理层”企业化闭环，优先实现三条必须能力：

1. 可查询“一个需求覆盖哪些用例”
2. 可查询“一个 Bug 影响哪些用例”
3. 可查询“一个代码改动触发哪些测试”

---

## 1. 执行总览（按流程层分解）

| 流程层 | 目标能力 | 本期交付 |
|---|---|---|
| 输入源层 | PRD/Swagger/Git Diff 标准输入 | 统一输入 DTO 与入库校验 |
| AI 编排层 | 解析、覆盖矩阵、影响分析 | 标准化 `requirement_spec` 输出并落 trace link |
| 测试用例管理层 | 生命周期、审批、关系、映射、编排、治理 | 生命周期引擎 + 审批流 + trace 关系层 + case/script 强映射 |
| 测试资产中心 | 结构化持久化与审计留痕 | 新增关系表、审计表、索引与查询 API |
| 执行层 | Suite 选择与触发执行 | 变更触发选案（change impact selection） |
| 结果回写层 | Run/证据/Bug 反向关联 | run 结果回写 case 质量与 trace 图谱 |
| AI 反哺层 | 优化/删除/补充建议受控落地 | AI 建议单 + 审批后生效 |

## 2. 8 周里程碑计划（可执行排期）

## M0（第 1 周：2026-04-06 ~ 2026-04-12）- 基线冻结与设计评审

交付项：

- D0.1 冻结 ER（Requirement/Case/Run/Bug/Change/Script）
- D0.2 冻结状态机与审批动作词典
- D0.3 冻结 API 合约（查询三条必须能力）

验收标准：

- 评审通过并形成文档版本号
- 后续开发不再改核心命名与主键规则

## M1（第 2-3 周：2026-04-13 ~ 2026-04-26）- 生命周期 + 审批 + 审计（P0）

交付项：

- D1.1 生命周期状态机：`Draft -> Review -> Approved -> Active -> Deprecated`
- D1.2 审批流最小可用：提交、审核通过、驳回、重提
- D1.3 审计日志：记录状态变更、审批动作、关键字段变更

验收标准：

- 任一 Case 状态变化均可追溯操作者和时间
- 审批链可回放（时间线）
- 审计日志支持按 `case_id` 查询

## M2（第 4-5 周：2026-04-27 ~ 2026-05-10）- 关系层 + 自动化强映射（P1）

交付项：

- D2.1 Requirement↔Case 关系落库与查询
- D2.2 Case↔Script 强映射（支持 1:N，含 manual/auto/hybrid 状态）
- D2.3 Case↔Run↔Bug 关系统一
- D2.4 Change↔Case 影响关系入库（基于 Git Diff）

验收标准：

- 通过 `requirement_id` 查询覆盖 case 列表
- 通过 `bug_id` 查询受影响 case 列表
- 通过 `commit_sha` 输出建议执行 case/suite 列表

## M3（第 6-7 周：2026-05-11 ~ 2026-05-24）- 选择编排 + CI/CD 触发（P1）

交付项：

- D3.1 Suite 实体与选案规则（tag/module/risk/change-impact）
- D3.2 变更触发执行链路（CI 调用选案 API）
- D3.3 执行结果回写 trace 图谱

验收标准：

- 代码变更后可自动生成建议回归集
- 执行完成后 case 维度可看到 run 与证据索引

## M4（第 8 周：2026-05-25 ~ 2026-05-31）- 治理闭环 + AI 反哺（P2）

交付项：

- D4.1 质量治理看板：覆盖率、失败率、波动率、陈旧度
- D4.2 AI 建议单（优化/删除/补充）并接入审批流
- D4.3 周报模板固化（管理层可读）

验收标准：

- 每周可自动输出低质量用例清单
- AI 建议默认不直接落库，审批后生效

## 4. 关键依赖与风险控制

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 历史 ID 不统一 | 关系表关联失败 | 增加 `legacy_case_id` 映射表，灰度迁移 |
| 生命周期改造影响现网 | 老接口兼容问题 | 提供兼容层与双写过渡期 |
| Git Diff 影响分析误报 | 触发集过大或遗漏 | 先以“建议执行”模式上线，人工确认后再自动 |
| 审计日志量增长快 | 查询慢、存储压力 | 分区/归档策略 + 索引治理 |
| AI 建议不稳定 | 错误变更风险 | 严格审批门禁，默认不自动生效 |
