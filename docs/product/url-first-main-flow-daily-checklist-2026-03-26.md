## 3. 今日执行顺序

### Step 1：固定样板输入

先不要碰别的页面。

固定这些输入：

- 页面：`http://localhost:5173/#/oms/returnApply`
- 工作台：`http://127.0.0.1:8013/workbench`
- 用例：`SMOKE-RETURNAPPLY-SEARCH-SERVICE-NO-3`

目的：

- 防止今天的工作再分叉到别的模块
- 保证调试时上下文一致

### Step 2：确认工作台选中链路

要检查：

- 用例列表是否能刷新出来
- 选中后 YAML 是否加载
- `当前用例` 是否变成真实 ID

如果这里失败，优先处理的是工作台选中链路，不是 runner 本身。

### Step 3：确认执行链路

要检查：

- 点击 `Run Test` 是否真正触发执行
- 是否进入 run 状态
- 是否打开 SSE/事件流

如果这里失败，优先看：

- 选中状态有没有传进去
- `case_id` 是否缺失
- 当前 run 是否成功创建

### Step 4：确认日志链路

要检查：

- `Realtime Logs` 有没有输出
- 有没有 `[run] command=...`
- 有没有 run 结束状态

如果这里失败，优先看：

- 事件流是否断开
- 后端运行时是否报错
- 前端是否没订阅到状态变化

### Step 5：确认失败回显链路

要检查：

- `Failure Analysis` 是否能显示失败原因
- `Download Log` 是否可用
- 失败记录是否能回到 run 页面

如果这里失败，优先看：

- run 记录是否有保存
- failure analysis 是否生成
- 证据目录是否存在

## 6. 今日可能遇到的卡点

### 卡点 1：`请先选择用例`

说明：

- 说明只是把 YAML 放进编辑器，但没有选中实际用例

处理：

- 先点击用例行
- 再看右侧是否真正载入

### 卡点 2：`BASE_URL is unreachable`

说明：

- 前置连通性不通

处理：

- 先确认前端服务是否在线
- 再确认容器内 BASE_URL

### 卡点 3：日志不刷新

说明：

- 事件流可能没有建立成功

处理：

- 先确认 run 状态是否创建
- 再确认日志事件是否绑定

### 卡点 4：失败分析为空

说明：

- 可能是 run 没有真正结束
- 也可能是失败证据没有写入

处理：

- 先确认终态
- 再看分析接口是否有返回
