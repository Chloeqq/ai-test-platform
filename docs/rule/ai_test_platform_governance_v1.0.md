# AI自动化测试平台基础治理规范 v1.0

**版本**：v1.0  
**适用范围**：AI自动化测试平台（Case / Suite / Plan / Run / Result 全链路）  
**目标**：建立平台级基础治理基线，避免架构反复重构、数据污染、AI产出不可控

---

# 1. 核心设计原则

## 1.1 一切必须结构化
- 禁止关键字段自由输入
- 必须字典化 + 枚举化

## 1.2 AI 只是生产者，不是规则制定者
- AI 不负责生成 ID
- AI 不负责定义结构
- AI 只能填充受控字段

## 1.3 平台强校验 > 提示词约束
- 所有数据必须经过系统校验
- 不合规数据不得入库

## 1.4 数据可追溯
- 每次变更必须可回溯
- AI 与人工修改必须区分

---

# 2. 核心领域模型

## 2.1 核心对象

| 对象 | 说明 |
|------|------|
| Case | 测试用例 |
| Suite | 测试套件 |
| Plan | 测试计划 |
| Run | 执行任务 |
| Result | 执行结果 |
| Bug | 缺陷 |
| Page | 页面 |
| Module | 模块 |

---

## 2.2 关系定义

- Case ∈ Module
- Module ∈ Page
- Case ↔ Suite（多对多）
- Suite ∈ Plan
- Plan → Run
- Run → Result

---

# 3. ID 规范

## 3.1 Case ID

```
[项目]-[端]-[页面]-[模块]-[类型]-[来源]-[序号]
```

示例：

```
ATP-WEB-RET-ORD-SM-AI-0001
```

---

## 3.2 ID 原则

- 平台生成，不允许手填
- 全局唯一
- 不可变（immutable）

---

# 4. 字典与枚举规范

## 4.1 必须字典化字段

- 项目
- 页面
- 模块
- 类型
- 来源
- 优先级
- 状态
- 标签分类

---

## 4.2 禁止

❌ 手动输入枚举  
❌ 自由拼写  
❌ 多语言混用  

---

# 5. 状态机规范

## 5.1 Case 状态

```
Draft → Review → Ready → Deprecated
```

---

## 5.2 Run 状态

```
Queued → Running → Passed / Failed / Blocked / Skipped
```

---

## 5.3 AI 状态

```
Generated → Reviewed → Accepted / Rejected
```

---

# 6. 版本管理规范

## 6.1 必须字段

- case_id
- version_no
- is_latest

---

## 6.2 规则

- 修改 Case 必须生成新版本
- Run 必须绑定 version
- 报告记录 version

---

# 7. AI 生成规范

## 7.1 AI 能做什么

- 生成 Case Draft
- 填充步骤 / 预期
- 推荐标签

---

## 7.2 AI 不能做什么

- 生成最终 ID
- 修改正式用例
- 创建字典项

---

## 7.3 来源定义

| code | 含义 |
|------|------|
| AI | AI生成 |
| CV | AI+人工确认 |
| MN | 人工 |
| IMP | 导入 |
| FB | fallback |
