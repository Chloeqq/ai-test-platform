# 页面对象治理高保真交互稿说明 V1.0

## 文档目标

在低保真线框基础上，进一步明确页面接近开发实现所需的交互细节，包括：

- 页面视觉层级与区块优先级
- 组件尺寸与布局建议
- 状态切换与按钮优先级
- 弹窗、抽屉、表格、筛选区的行为规范
- 页面之间的联动反馈

本文不是视觉稿，但已经足够指导前端开发与 UI 设计统一实现。

---

## 一、整体设计基调

### 1. 页面气质

页面对象治理不是内容消费型页面，而是“资产判断 + 批量处理”的工作台。

所以整体页面气质建议：

- 专业、稳定、密度适中
- 信息优先级清晰
- 不追求花哨，而追求判断效率
- 高风险操作显式提醒

### 2. 页面密度建议

建议采用中高信息密度：

- 列表页允许首屏展示 8 到 12 行
- 表格行高不宜过高
- 摘要卡简洁，避免大块空白
- 详情使用抽屉承载，减少页面跳转

### 3. 全局布局建议

- 页面主内容宽度：自适应全宽
- 内容左右留白：24px
- 主区块间距：16px
- 表格区与筛选区间距：12px
- 卡片内边距：16px
- 弹窗内边距：20px

### 4. 颜色语义

- 主操作按钮：深蓝或品牌主色
- 次操作按钮：白底描边
- 成功状态：绿色
- 待处理状态：橙色
- 危险状态：红色
- 弱化信息：灰色

### 5. 字体层级

- 页面标题：20px / semibold
- 分区标题：16px / semibold
- 普通正文：14px
- 辅助说明：12px
- 表格内容：13px 或 14px

## 二、页面对象列表页高保真说明

页面：`PageObjectsPage`

### 1. 页面结构层级

从上到下：

1. 页面标题与主操作区
2. 治理摘要卡
3. 筛选条
4. 列表表格
5. 分页

### 2. 页面标题区

左侧：

- 标题：`页面对象`
- 副标题：`统一管理页面资产、录制过程与元素治理状态`

右侧：

- 主按钮：`新建页面对象`

交互建议：

- 主按钮固定为实心按钮
- 如果后续支持批量导入，可放在按钮右侧次级菜单中，不影响当前主按钮唯一性

### 3. 摘要卡设计

建议 4 张卡并排，超窄屏时自动换两行。

卡片内容：

1. 页面总数
2. 已治理页面数
3. 待审候选组总数
4. 平均可测试性评分

每张卡结构：

- 顶部小标题
- 中间大数字
- 底部辅助说明

例如：

- 标题：`待审候选组`
- 数字：`24`
- 辅助：`较昨日 +3`

如果当前没有环比数据，底部显示：

- `当前项目待处理候选总量`

### 4. 筛选区设计

建议采用单行可换行筛选条。

控件顺序：

- 项目
- 端类型
- 模块
- 页面状态
- 治理状态
- 关键词搜索
- 查询
- 重置

交互规则：

- `项目` 为必选，默认填当前项目
- `关键词` 支持搜页面编码、页面名称、URL
- 查询按钮为主按钮
- 重置按钮为次按钮

### 5. 表格高保真说明

#### 列顺序

- 页面编码
- 页面名称
- 页面地址 / Route
- 正式元素数
- 待审候选组
- 关键元素覆盖率
- 可测试性评分
- 治理状态
- 最近录制时间
- 更新时间
- 操作

#### 重点列视觉处理

`待审候选组`

- 若大于 0，用橙色数字标签强调
- 若等于 0，用灰色 `0`

`关键元素覆盖率`

- 数字 + 细进度条
- 小于 60% 用橙色
- 小于 30% 用红色

`可测试性评分`

- 展示 `82`
- 下方加极细色条
- 80 以上绿色，60 到 79 橙色，60 以下红色

`治理状态`

- `draft` -> 灰色标签 `草稿`
- `active` -> 绿色标签 `已可用`
- `governing` -> 橙色标签 `治理中`
- `retired` -> 深灰标签 `已下线`

### 6. 操作列设计

建议操作列只露出两个高频动作，其余收纳：

- 主文本按钮：`查看元素`
- 次文本按钮：`开始录制`
- 更多菜单：
  - 编辑页面
  - 删除

这样能减少表格右侧拥挤。

### 7. 空状态

无页面对象时展示：

- 标题：`还没有页面对象`
- 说明：`建议先创建页面对象，再开始录制和治理元素资产`
- 按钮：`新建页面对象`

## 三、页面对象录制页高保真说明

页面：`PageObjectRecorderPage`

### 1. 页面结构层级

从上到下：

1. 页面头部信息卡
2. 录制控制区
3. 当前会话面板 + 最近录制历史
4. 停止后的结果卡

### 2. 页面头部信息卡

左侧展示：

- 页面名称 + 页面编码
- URL / route
- 治理状态
- 正式元素数
- 待审候选组数

右侧展示：

- 返回元素列表
- 刷新
- 开始录制 / 停止录制

状态规则：

- 非录制中：展示 `开始录制`
- 录制中：主按钮切换为红色 `停止录制`

### 3. 当前会话面板

建议做成重点卡片。

结构：

- 顶部：状态标签 + 会话 ID
- 中部：两列信息
- 底部：stderr 摘要区域

信息字段：

- 启动时间
- 最近心跳
- 当前状态
- 脚本路径

状态标签建议：

- 启动中：蓝色
- 录制中：绿色闪点
- 已停止：灰色
- 启动失败：红色

### 4. 最近录制历史

建议表格高度控制，首屏展示最近 5 条。

每行操作：

- 查看回放
- 去审核
- stderr

若该条记录已有候选组，则 `去审核` 高亮显示。

### 5. 停止后的结果卡

该卡片出现时，页面要明显聚焦到这里。

建议：

- 出现在会话停止后
- 自动滚动到卡片区域

卡片结构：

- 顶部标题：`本次录制已完成`
- 中间 5 个摘要数字块
- 底部主操作区

数字块：

- 候选总数
- 候选分组数
- 推荐可提升数
- 页面匹配状态
- 回放步骤数

主操作区：

- 主按钮：`去元素列表审核`
- 次按钮：`查看回放`
- 次按钮：`查看脚本`
- 文本按钮：`重新录制`

### 6. 失败状态

如果录制失败：

- 结果卡标题改为 `录制启动失败`
- 主说明展示错误摘要
- 操作按钮改为：
  - 查看 stderr
  - 重新录制

不展示“去元素列表审核”。

## 五、正式元素 Tab 高保真说明

### 1. 筛选区

布局建议：

- 第一行：关键词、业务类型、审核状态、稳定等级
- 第二行：定位来源、是否关键元素、查询、重置

关键词搜索框应较宽，支持输入编码、名称、别名。

### 2. 表格设计

#### 列视觉优先级

第一优先级：

- 元素编码
- 元素名称
- 业务类型
- 审核状态
- 稳定等级

第二优先级：

- 业务域
- 主定位来源
- 关键元素
- 引用次数

第三优先级：

- 更新时间

#### 行状态表达

`审核状态`

- approved：绿色标签 `已审核`
- pending：橙色标签 `待审核`
- rejected：红色标签 `已拒绝`

`稳定等级`

- high：绿色标签 `高`
- medium：橙色标签 `中`
- low：红色标签 `低`

`关键元素`

- 是：深色强调标签 `关键`
- 否：灰色短横

### 3. 行 hover 行为

鼠标悬停一行时：

- 背景轻微高亮
- 操作列按钮出现完整

默认只显示：

- 查看详情
- 编辑

更多菜单中：

- 查看定位器
- 查看引用
- 标记待治理

### 4. 详情抽屉

抽屉宽度建议：`520px - 640px`

顶部：

- 元素名称
- 元素编码
- 审核状态标签
- 稳定等级标签

中部按模块分区：

1. 基本信息
2. 主定位信息
3. 扩展定位器
4. 语义信息
5. 治理信息

#### 扩展定位器显示建议

采用小表格：

- 定位类型
- 定位值
- 来源
- 优先级
- 验证状态

#### 特殊提示

若 `stability_level=low`

- 在抽屉顶部信息下方出现黄色提示：
  - `当前元素稳定性较低，默认不参与新映射链路`

若 `review_status!=approved`

- 再出现一条灰橙提示：
  - `当前元素未通过审核，不参与新测试点映射`

### 5. 编辑弹窗

弹窗宽度建议：`720px`

布局：

- 左右两列表单

左列：

- 元素编码
- 元素名称
- 业务类型
- 业务域
- 别名
- 语义标签

右列：

- route_scope
- 是否关键元素
- testid_value
- qa_value
- 主定位器
- 审核说明

交互规则：

- 修改是否关键元素后，立即联动 testid/qa 校验
- 如果业务类型选择 `password_toggle`
  - 在字段下展示提示：
    - `建议关联 password_input 使用，不建议按纯 text 定位`

## 六、候选元素 Tab 高保真说明

这是全套交互的核心。

### 1. 页面布局

建议采用两栏布局：

- 左侧候选分组表：70%
- 右侧详情面板：30%

右侧详情固定在页面内，不另开新页。

### 2. 分组表设计

#### 表头列

- 选择框
- 建议编码
- 建议名称
- 类型猜测
- 质量等级
- 候选数
- 会话数
- 推荐动作
- 已匹配正式元素
- 状态
- 最近更新时间
- 操作

#### 列显示规则

`质量等级`

- A：绿色
- B：橙绿
- C：橙色
- D：红色

`推荐动作`

- promote：蓝绿标签 `建议提升`
- review：橙色标签 `建议复核`
- skip：灰色标签 `建议跳过`

`状态`

- pending：橙色 `待处理`
- partially_promoted：蓝色 `部分已提升`
- promoted：绿色 `已提升`
- rejected：灰色 `已拒绝`

### 3. 选中分组行为

点击任意一行：

- 右侧详情面板加载对应 group 详情
- 当前行高亮
- 若 URL 未带 `group_key`，可同步写入 query，便于刷新保留上下文

### 4. 右侧详情面板结构

顶部摘要：

- 建议名称
- 建议编码
- 质量等级
- 推荐动作
- 状态

中间信息区分三块：

1. 语义与分组信息
2. 定位概况
3. 风险提示

底部是候选明细表。

### 5. 候选明细表高保真说明

列：

- locator_type
- locator_value
- role
- route
- step_hit_count
- score
- probe 状态
- 来源 session
- 状态
- 操作

表现规则：

`score`

- 显示数值
- 同时配一个很细的色条

`probe 状态`

- ok：绿色
- unknown：灰色
- not_found：红色
- ambiguous：橙色

`locator_value`

- 长文本默认单行截断
- hover 显示完整 tooltip

### 6. 候选 Tab 的主次操作规则

左侧表格行操作：

- 主按钮：`查看候选`
- 次按钮：`提升`
- 更多菜单：
  - 合并到已有正式元素
  - 批量拒绝组内候选
  - 编辑建议编码/名称/语义

右侧详情底部操作：

- 主按钮：`提升为正式元素`
- 次按钮：`合并到已有正式元素`
- 危险按钮：`批量拒绝组内候选`

### 7. 提升弹窗高保真说明

弹窗尺寸建议：

- 宽度 `860px`
- 高度自适应，最长内容可滚动

布局：

- 左 40%：候选摘要
- 右 60%：正式元素表单

#### 左侧候选摘要

模块顺序：

1. 推荐编码 / 名称
2. 业务类型猜测
3. 主定位候选
4. route_scope
5. 风险提示

#### 右侧表单

字段顺序：

- 元素编码
- 元素名称
- 业务类型
- 业务域
- 是否关键元素
- testid_value
- qa_value
- route_scope
- 主定位器选择
- 审核说明

#### 实时校验区

显示在弹窗底部上方，实时刷新：

- 编码规则校验
- 编码唯一校验
- 关键元素契约校验
- 主定位器稳定性判断

校验结果格式建议：

- 通过：绿色对勾 + 文案
- 风险：橙色提示 + 原因
- 不通过：红色提示 + 阻断原因

#### 提交规则

- 所有阻断项通过后，`确认提升` 才可点击
- 提交成功：
  - 关闭弹窗
  - 刷新分组表
  - 刷新右侧详情
  - 刷新正式元素统计
  - 弹出成功反馈：
    - `已创建正式元素，可切换到“正式元素”查看`

### 8. 合并弹窗高保真说明

尺寸建议：

- 宽度 `760px`

结构：

1. 左侧候选摘要
2. 右侧已有正式元素选择器
3. 底部影响说明

元素选择器建议支持：

- 搜索
- 业务类型优先推荐
- 结果列表展示审核状态与稳定等级

底部影响说明要明确：

- 是否新增备选定位器
- 是否覆盖主定位器

默认策略：

- 不覆盖主定位器
- 仅新增到 `page_element_locators`

### 9. 拒绝弹窗高保真说明

尺寸建议：

- 小弹窗 `480px`

字段：

- 拒绝原因下拉
- 审核说明文本域

交互规则：

- 审核说明必填
- 点击确认后更新状态，不关闭右侧详情上下文

成功提示：

- `已拒绝并记录原因`

### 10. 批量操作条

当左侧表格选择多行时，在表格顶部出现批量操作条：

- 已选择 `N` 项
- 按钮：批量拒绝
- 清空选择

第一版如果不做批量提升，也要保留批量拒绝的入口。

## 八、跨页面联动规则

### 1. 从录制页跳到候选元素页

跳转时带参数：

- `project`
- `tab=candidates`
- `session_id`

进入后页面行为：

- 自动激活 `候选元素` Tab
- 自动填充 `session_id` 筛选
- 自动查询
- 若结果只有一个分组，自动选中并展开详情

### 2. 候选提升成功后的联动

页面需要同步更新：

- 顶部治理摘要卡
- 候选分组状态
- 候选组数
- 正式元素数

不建议强制跳走到正式元素 Tab，因为用户通常还要继续处理下一组。

### 3. 正式元素编辑后的联动

更新内容后：

- 刷新当前详情抽屉
- 刷新正式元素表格该行
- 如影响摘要卡，则刷新摘要

### 4. 拒绝候选后的联动

拒绝后：

- 更新当前 group 状态
- 更新组内候选状态
- 刷新待审候选组数

## 九、反馈与提示规范

### 1. 成功提示

- 提升成功：`已创建正式元素`
- 合并成功：`已合并到正式元素，并保留备选定位器`
- 拒绝成功：`已拒绝并记录原因`
- 编辑成功：`已更新元素信息`

### 2. 失败提示

尽量给具体原因，不要只写操作失败。

例如：

- `提升失败：关键元素必须提供 testid 或 qa 标识`
- `提升失败：元素编码已存在`
- `合并失败：目标正式元素不存在或已失效`

### 3. 阻断型确认

以下操作必须二次确认：

- 删除页面对象
- 批量拒绝候选
- 合并到已有正式元素

---

## 十、响应式建议

### 1. 窄屏处理

当宽度不足时：

- 摘要卡改两行
- 表格允许横向滚动
- 候选元素页右侧详情面板改为抽屉模式

### 2. 中屏处理

- 列表与详情面板仍可共存
- 但右侧详情宽度适当压缩

### 3. 桌面优先

由于该页面主要服务资产治理与批量审核，优先优化桌面体验。

---

## 十一、推荐前端落地顺序

1. 先实现整体页面壳子、头部信息、摘要卡、Tab 结构
2. 再实现正式元素 Tab 表格与详情抽屉
3. 再实现候选元素 Tab 左右布局
4. 再实现提升 / 合并 / 拒绝弹窗
5. 最后打磨录制页停止结果卡与录制历史回放抽屉

---

## 十二、最终建议

如果把这套页面理解成一句话：

- 页面对象列表页负责“找页面”
- 录制页负责“产候选”
- 元素列表页负责“做治理”

真正需要最精细设计和最高完成度的，是元素列表页里的候选元素 Tab。这里只要顺，整套页面对象治理闭环就顺了。
