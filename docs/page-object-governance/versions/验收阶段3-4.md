阶段 3 验收：治理页面交互
当前页面：/react/assets/page-objects/profile/elements?project=atp

打开元素列表页，确认有 3 个 Tab：正式元素、候选元素、录制历史。
正式元素 Tab：点击某个元素的查看/编辑，详情里应能看到业务类型、定位来源、稳定等级、审核状态、关键元素、别名、引用等信息。
候选元素 Tab：应按“候选分组”展示，不是直接平铺所有候选明细。
点击候选分组的“查看候选”，右侧应展示组内候选明细，包括 locator、role、score、risk_tags、session。
对候选执行：
提升为正式元素：成功后候选状态变成 promoted，正式元素列表新增元素。
合并到已有正式元素：成功后候选状态变成 merged，并生成备选定位器。
拒绝候选：必须填写原因，成功后状态变成 rejected。
录制历史 Tab：应能看到 session、候选数、候选组数、已提升数、已拒绝数，并能查看回放/脚本/跳转候选过滤。
阶段 4 验收：命名规范与校验
重点看 element_code 是否真正被系统约束住。

在候选提升弹窗里填非法编码，例如 login-css-i-path-3、page_profile_username_input、button_1，应被前端提示阻止，后端也应返回 invalid_element_code。
合法业务编码应允许，例如 username_input、order_no_column、product_name_input、user_role_select、rich_text_editor。
business_type=password_toggle 时，编码必须是 password_toggle。
business_type=metric_value 时，编码必须以 _metric_value 结尾。
在正式元素的“编辑语义”里，历史脏编码现在应支持手动改成合法编码，并保存成功，原引用不应丢失。
普通新建正式元素不能绕过审核直接变成 approved/high；普通创建仍应是 pending/low，候选提升才允许进入 approved/high。
