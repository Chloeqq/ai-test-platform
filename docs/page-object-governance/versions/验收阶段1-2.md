阶段 1 验收：资产模型纠偏
验收目标：正式元素、候选元素、治理日志、扩展定位器这些资产边界已经分清楚。

你可以验收这些点：

数据库结构存在并可迁移

page_objects 已有治理字段：governance_status、testability_score、candidate_pending_count 等。
page_elements 已有治理字段：business_type、review_status、stability_level、locator_source、is_key_element 等。
新表存在：page_object_candidate_groups、page_object_candidate_elements、page_element_locators、page_object_governance_logs。
普通正式元素创建不能绕过审核

调用普通创建元素接口时，即使传 review_status=approved、stability_level=high，最终也应该是 pending + low。
这说明“人工审核/候选提升”才是 approved 的入口。
查询接口没有写副作用

刷新页面对象列表、元素列表，不应该删除任何数据。
去重或物理删除只能通过显式删除/去重接口触发。
治理统计能正确返回

页面对象详情或 governance summary 能看到正式元素数、已审核元素数、待审候选组数、关键元素数等。
新增候选组后，待审候选组数应该能反映出来。
治理字段修改有审计

修改正式元素的 review_status、stability_level、business_type 等字段后，page_object_governance_logs 应有记录。
阶段 2 验收：录制链路纠偏
验收目标：录制停止后默认进入候选治理层，不再污染正式元素。

你可以这样验收：

启动一次页面对象录制

在录制页创建 session。
执行几个操作，例如输入账号、点击按钮、点击文本。
停止录制。
停止录制后看返回结果

ingested_count 应为 0。
page_element_total_count 不应因为本次录制增加。
返回里应该有：
candidate_count
candidate_group_count
promotable_count
element_candidates
查正式元素列表

本次录制的新元素不应该出现在正式元素列表里。
这点是阶段 2 最关键验收项。
查候选数据表

page_object_candidate_elements 应有本次 session 的候选明细。
page_object_candidate_groups 应有对应候选分组。
候选默认状态应是 pending。
分组默认状态应是 pending。
重复点击停止录制

不应重复创建正式元素。
不应丢失候选状态。
如果某个候选已被标记为 reviewed/rejected/promoted/merged，重复 stop 后状态不能变回 pending。
录制历史和回放

录制历史列表能看到 session。
回放接口能返回录制步骤、脚本、候选摘要。
历史列表不应因为数据多而明显卡顿。
