# 页面对象治理执行计划方案 V1.0

## 文档目标

本文用于统一后续执行节奏，明确项目目标、阶段拆分、当前跑偏点、纠偏策略与验收标准。

核心原则：

- 先把页面对象资产治理链路做对，再让它支撑测试点映射和可执行用例生成。

---

## 一、项目目标

最终目标不是“录制更多 locator”，也不是“尽快生成更多测试用例”，而是形成一条稳定闭环：

1. 识别页面对象
2. 采集候选元素
3. 治理候选元素
4. 形成正式元素资产
5. 用正式元素映射测试点
6. 生成可执行测试用例
7. 执行失败后可回溯、可修复、可持续治理

---

## 二、当前跑偏点

### 1. 录制结果被直接当成正式元素

`Playwright codegen` 的产物是运行时候选，不是正式资产。当前如果直接入库到正式元素，会导致资产库被 locator 噪音污染。

纠偏：

- 录制只写候选层
- 正式元素必须审核提升

### 2. 元素编码命名是实现导向

例如：

- `login-css-i-path-3`
- `text-2`
- `button-1`

这些名字无法稳定映射测试点。

纠偏：

- 正式 `element_code` 必须采用业务语义命名
- 统一 `snake_case`
- 禁止 locator 噪音词

### 3. 页面对象、页面元素、测试点之间缺少强约束

当前链路更像弱关联，导致生成步骤时容易退回到原始 locator 或文本猜测。

纠偏：

- 新测试点映射只使用合格正式元素
- 不允许新治理链路回退 raw locator

### 4. 录制链路和治理链路职责混在一起

录制页不应该承担完整审核职责。

纠偏：

- 录制页只负责产候选和跳转治理
- 元素列表页承担候选审核

### 5. 候选层和正式层边界不清

没有清晰区分：

- 候选元素
- 正式元素
- 历史脏数据
- 可参与映射的正式元素

纠偏：

- 新增候选分组表与候选明细表
- 正式元素增加审核状态和稳定性等级

### 6. 数据结构偏 CRUD 台账，不足以支撑治理闭环

缺少：

- 候选分组
- 候选明细
- 多定位器扩展
- 治理日志

纠偏：

- 补齐治理数据模型

### 7. 下游生成链路过早依赖不可靠元素

页面元素质量不可靠时，用例生成必然不稳定。

纠偏：

- 先治资产
- 再接测试点映射
- 最后接执行闭环

### 8. mall-admin-web 适配策略不完整

无前端开发配合的开源项目，不能只靠源码，也不能只靠 codegen。

纠偏：

- codegen 负责候选采集
- 源码负责语义增强
- 治理页负责人工归一

## 三、执行阶段

## 阶段 0：方案冻结与口径统一

目标：

- 固定后续执行口径，避免边做边漂。

输出物：

- 页面对象治理方案
- UI/交互方案
- 前端实现规格
- 元素获取策略与命名规范
- 执行计划方案

完成标准：

- 方案文档全部落盘
- 后续开发按文档执行

## 阶段 1：资产模型纠偏

目标：

- 建立候选、正式、治理日志、多定位器的清晰数据边界。

要做：

- 扩展 `page_objects`
- 扩展 `page_elements`
- 新增 `page_object_candidate_groups`
- 新增 `page_object_candidate_elements`
- 新增 `page_element_locators`
- 新增 `page_object_governance_logs`
- 标记历史脏元素

完成标准：

- 数据库能承载“候选 -> 审核 -> 正式”的完整流程

## 阶段 2：录制链路纠偏

目标：

- 录制只生产候选，不直接生产正式元素。

要做：

- 改造 `stop_recorder_session`
- 持久化候选元素
- 聚合候选分组
- 返回候选摘要
- 保留回放与录制历史

完成标准：

- 停止录制后新增候选分组和候选明细
- 不新增正式元素

## 阶段 3：治理页面纠偏

目标：

- 元素列表页成为治理中枢。

要做：

- 页面对象列表页增加治理总览
- 元素列表页改为三 Tab
- 候选分组表和详情面板
- 提升、合并、拒绝流程
- 录制历史 Tab

完成标准：

- 用户能在元素列表页完成候选审核与正式元素治理

## 阶段 4：命名规范与校验器落地

目标：

- 让元素编码规范从文档变成系统规则。

要做：

- `element_code` 正则校验
- 禁止词校验
- 页面前缀禁用校验
- 特殊语义类型校验
- 推荐编码提示

完成标准：

- 脏命名无法进入正式元素库

## 阶段 5：源码语义增强接入

目标：

- 为 `mall-admin-web` 这类无测试契约项目补语义能力。

要做：

- 提取 route
- 提取菜单标题
- 提取表单 label
- 提取按钮文本
- 提取表格列名
- 辅助候选命名和类型猜测

完成标准：

- 候选建议命名质量明显优于纯 codegen

## 阶段 6：测试点映射链路纠偏

目标：

- 只允许高质量正式元素参与测试点映射。

要做：

- 调整映射规则
- 只使用 `approved + high/medium + active`
- 排除 `low/pending/rejected`
- 增加映射失败原因
- 增加特殊语义映射规则

完成标准：

- 测试点映射不再依赖未治理 locator

## 阶段 7：生成与执行闭环纠偏

目标：

- 生成、执行、失败回溯、治理修复形成闭环。

要做：

- 生成链路读取正式元素资产
- 执行链路记录命中元素
- 失败回溯到页面元素
- 失败原因反哺治理页

完成标准：

- 执行失败能回流到资产治理

---

## 四、推荐推进顺序

实际开发建议按以下顺序：

1. 阶段 1：资产模型纠偏
2. 阶段 2：录制链路纠偏
3. 阶段 3：治理页面纠偏
4. 阶段 4：命名规范与校验器落地
5. 阶段 6：测试点映射链路纠偏
6. 阶段 5：源码语义增强接入
7. 阶段 7：生成与执行闭环纠偏

原因：

- 没有正确模型，前端治理会空转
- 没有候选层，录制链路会继续污染正式元素
- 没有命名和审核，测试点映射会继续漂

---

## 五、阶段验收标准

### 阶段 1

- 能区分正式元素、候选分组、候选明细、治理日志
- 历史正式元素可标记为低稳定性待治理

### 阶段 2

- 停止录制后不会新增正式元素
- 会生成候选分组和候选明细

### 阶段 3

- 元素列表页能完成提升、合并、拒绝
- 录制页只负责跳转治理

### 阶段 4

- 不符合规范的编码无法提升
- 特殊语义类型可正确保存

### 阶段 5

- 候选建议命名质量提升
- 常见表单、按钮、表格元素可被语义增强

### 阶段 6

- 测试点映射默认只读合格正式元素
- 映射失败原因可解释

### 阶段 7

- 执行失败可定位到页面元素资产问题
- 可回流治理

---

## 六、协作方式

后续执行时按阶段推进：

1. 进入阶段前，先拆开发清单
2. 开发过程中持续检查是否偏离目标
3. 阶段完成后做验收复盘
4. 发现跑偏立刻纠正，不把错误路线继续做深
