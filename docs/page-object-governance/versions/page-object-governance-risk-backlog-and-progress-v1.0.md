# 页面对象治理风险留存与进度 V1.0

## 总体进度

截至当前阶段，页面对象治理主链路已完成约 95%。

- 阶段 1 资产模型纠偏：已完成，剩余为持续回归验证。
- 阶段 2 候选治理入库：已完成，录制默认进入候选层，不直写正式元素。
- 阶段 3 前端治理交互：主要链路已完成，仍需继续做组件化收口。
- 阶段 4 元素编码与审核修复：主要链路已完成，历史脏数据修复路径已具备基础能力。
- 阶段 5 源码语义增强：已完成基础多项目隔离，后续继续依赖项目级源码与术语配置。
- 阶段 6 编译映射治理：已完成严格治理校验，未治理 YAML 不再进入新映射链路。
- 阶段 7 失败反哺治理：已完成基础失败元素影响定位，仍需继续提升报告页产品体验。
- 前端产品化收口：已完成首批基础组件沉淀，核心资产页和大部分业务列表页已统一空态、状态标签、指标卡、筛选区、表格壳和批量操作条。

## 已收口问题

- 治理指标同步 helper 已改为 `flush`，不再内部 `commit`，由上层事务统一提交。
- 通用元素命名策略已移除 mall-admin-web 专属业务词，仅保留通用动作和控件语义。
- 源码语义层已移除全局 mall 术语兜底，mall 术语应通过项目级 `source_terms_json` 或环境变量配置。
- 页面对象 ORM 默认项目已统一为 `mall`。
- 录制停止接口已禁止直写正式元素，录制结果默认进入候选治理层。
- 阶段 6 严格治理回归测试已覆盖：DB 查询异常不回退 YAML、未治理页面对象阻断 YAML fallback、`metric_value` 不参与 `assert_metric`。
- 前端已新增 `EmptyState`、`StatusPill`、`BulkActionBar`、`MetricCards`、`FilterBar`、`DataTable` 基础组件，并在页面对象、元素治理、测试点资产等核心页面首批落地。
- 核心资产页和报告/执行/质量/项目/调度页面的筛选区已统一为 `FilterBar`，标准列表基本已使用 `DataTable`。
- 详情页中的测试点明细、覆盖矩阵、执行摘要、录制历史也已收口到 `DataTable`。
- 阶段 7 风险复核已完成：生产静态 React 包已通过 `npm run build` 更新；正式元素审核资格校验已有回归覆盖；元素更新事务保持一次提交；执行记录项目归属已优先从测试用例读取。
- Runner case_id 解析已修复为保留原始用例 ID，同时 YAML 查找兼容原始 ID 与规范化 ID，避免报告和用例资产追溯错位。
- 核心资产页空状态已从“暂无数据”升级为带下一步提示的产品化空态。

## 当前留存问题

- `P1` 前端产品化收口：剩余重点转入超大页面拆分，尤其是 `PageObjectElementsPage` 和 `AiGenerationPage`。
- `P2` 视觉与组件体系：标准列表已基本统一，剩余主要是元素治理大页中的复杂内嵌表格和 CSS 分层。
- `P2` 时间与展示规范：新增页面禁止直接 `toLocaleString` 或局部实现 `formatDate`，统一使用 `formatDateTime`。
- `P3` 信息架构：导航后续建议按用户任务重组，空状态需要提示下一步动作。

## 下一步处理顺序

1. 拆分 `PageObjectElementsPage`，优先抽正式元素表、候选分组表、录制历史表和详情区域。
2. 拆分 `AiGenerationPage`，优先抽步骤区、候选预览区、预校验区和结果区。
3. 拆分 `styles.css` 为 tokens、layout、components、pages，降低样式串扰风险。
4. 后续做导航信息架构与空状态行动入口的精细化优化。
