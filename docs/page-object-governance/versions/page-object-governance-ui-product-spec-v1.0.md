# 页面对象治理产品与 UI 设计稿 V1.0

## 文档目标

基于当前已确认的页面对象治理方案，输出一套可直接指导前后端落地的页面级产品设计。重点解决四个问题：

- 页面怎么分层，用户从哪里进入治理链路
- 每个页面的信息结构怎么摆，哪些信息先看，哪些信息后看
- 审核、提升、合并、拒绝这些高频动作怎么做到顺手
- 怎么保证测试工程师在“录制 -> 审核 -> 提升 -> 映射 -> 生成用例”链路里不会迷路

本文默认面向角色：

- 测试工程师
- 测试开发 / 自动化工程师
- 资产治理管理员

## 一、整体产品结构

### 1. 资产治理主链路

建议将页面对象治理链路统一成 4 段：

1. 页面对象列表页
2. 页面对象详情-元素列表页
3. 页面对象录制页
4. 候选审核弹窗 / 详情抽屉 / 回放抽屉

用户主路径：

1. 在页面对象列表页找到目标页面
2. 进入录制页发起录制
3. 录制停止后跳去元素列表页的候选元素 Tab
4. 在候选分组里批量审核
5. 提升为正式元素
6. 正式元素参与测试点映射与可执行用例生成

### 2. 页面导航层级

建议采用两层结构，不新增独立“治理工作台”：

- 一级：页面对象列表
- 二级：某个页面对象下的元素治理页

录制页属于二级的辅助页面，不单独承担治理职责。

### 3. 核心设计原则

- 先总览，再下钻：先看页面级健康度，再看元素级问题
- 先正式资产，再候选治理：默认先展示正式元素，避免页面一打开就杂乱
- 让批量操作比单条操作更顺手：因为真实治理的工作量通常在批量
- 尽量让用户在一个页面完成判断：少跳转，多抽屉、多侧边详情
- 所有“危险动作”必须给出影响说明：例如拒绝、合并、提升关键元素

## 二、页面对象列表页

页面：`PageObjectsPage`

### 1. 页面定位

这是治理入口页，不做具体审核，只回答三个问题：

- 哪些页面资产已经成熟
- 哪些页面还缺关键元素
- 哪些页面最近录制了但还没治理

### 2. 布局结构

建议采用：

- 顶部：页面标题区 + 主操作区
- 中部：筛选条
- 下部：页面对象表格
- 右侧或底部：简版统计卡

页面结构：

1. 顶部标题区
   - 标题：页面对象
   - 副标题：管理页面资产、录制历史与元素治理状态
   - 主按钮：新建页面对象

2. 顶部统计卡
   - 页面总数
   - 已治理页面数
   - 待审核候选组总数
   - 平均可测试性评分

3. 筛选区
   - 项目
   - 端类型
   - 模块
   - 页面状态
   - 治理状态
   - 关键词搜索

4. 列表区

### 3. 表格列设计

- 页面编码
- 页面名称
- 页面地址 / route
- 正式元素数
- 待审候选组数
- 关键元素覆盖率
- 可测试性评分
- 治理状态
- 最近录制时间
- 更新时间
- 操作

### 4. 操作区设计

统一中文文案：

- 查看元素
- 开始录制
- 编辑页面
- 删除

去掉与此页职责不一致的动作：

- 不在列表页直接“生成用例”
- 不在列表页直接审核候选

### 5. 行状态表达

治理状态用有语义的标签：

- 草稿：灰色
- 治理中：橙色
- 已可用：绿色
- 已下线：深灰

可测试性评分建议同时显示：

- 分值
- 进度条

例如：

- `82 / 100`
- 下方细线进度条

### 6. 行点击逻辑

- 点击页面名称或“查看元素”进入元素列表页
- 点击“开始录制”进入录制页
- 点击“编辑页面”打开编辑弹窗
- 点击“删除”二次确认

### 7. 体验重点

- 用户进入列表 5 秒内应能知道“先治理哪个页面”
- 所以“待审候选组数”和“关键元素覆盖率”必须靠前
- 评分和状态必须一眼可比，不能藏在详情里

## 三、页面对象录制页

页面：`PageObjectRecorderPage`

### 1. 页面定位

录制页只负责：

- 发起录制
- 监控录制状态
- 停止录制
- 展示回放
- 引导跳转去治理

不负责：

- 正式元素审核
- 候选批量治理
- 正式元素编辑

### 2. 页面布局

建议三栏式信息，但视觉上做成上下两层：

1. 顶部区域：页面信息 + 录制控制
2. 中部左侧：当前会话状态 / 运行日志
3. 中部右侧：最近录制历史
4. 底部区域：停止录制后的结果卡片

### 3. 顶部信息卡

展示：

- 页面编码
- 页面名称
- 页面 URL
- 当前治理状态
- 已有正式元素数
- 待审候选组数

右侧按钮：

- 开始录制
- 停止录制
- 刷新状态

规则：

- 未录制时只亮“开始录制”
- 录制中只亮“停止录制”

### 4. 录制中状态面板

录制中页面不能太空，建议给到用户明确反馈：

- 会话 ID
- 启动时间
- 心跳时间
- 当前状态
- 录制脚本路径
- 最近 stderr 输出

状态展示：

- 启动中
- 录制中
- 已停止
- 启动失败

### 5. 停止录制后的结果卡片

这是录制页最关键的区域。

展示：

- 本次录制状态
- 候选总数
- 候选分组数
- 推荐可提升数
- 页面匹配状态
- 本次回放步骤数

主按钮：

- 去元素列表审核

次按钮：

- 查看回放
- 查看脚本
- 重新录制

### 6. 关键交互

点击“去元素列表审核”：

- 跳转到 `PageObjectElementsPage`
- 自动打开 `候选元素` Tab
- 自动带上 `session_id`

URL 形式建议：

- `/assets/page-objects/{pageCode}/elements?project=atp&tab=candidates&session_id=xxx`

### 7. 最近录制历史区

列表字段：

- 会话 ID
- 状态
- 开始时间
- 停止时间
- 候选数
- 候选组数
- 已提升数
- 已拒绝数
- 操作

操作：

- 查看回放
- 去审核
- 查看 stderr

### 8. 体验重点

- 录制停止后，用户必须知道下一步该去哪
- 所以“去元素列表审核”必须是停止后的最强主按钮
- 页面上不能再出现“直接生成正式元素”的竞争路径

- 正式元素

### 2. 总体布局

建议统一布局：

1. 顶部页面对象信息带
2. 治理摘要卡
3. Tab 区
4. 当前 Tab 的筛选条
5. 主表格
6. 右侧详情抽屉
7. 弹窗动作层

### 3. 顶部信息带

展示：

- 页面名称
- 页面编码
- route / URL
- 所属项目
- 页面状态
- 治理状态

右侧按钮：

- 开始录制
- 刷新数据
- 返回页面对象

### 4. 治理摘要卡

## 六、候选元素 Tab

这是整个产品里最重要的设计部分。

### 1. 页面目标

把“录制噪音”整理成“可审核资产”。

因此必须满足：

- 先按组看，不直接平铺明细
- 批量处理比单条处理更顺手
- 看得出为什么建议提升，为什么建议拒绝

### 2. 页面布局

建议采用“左主表 + 右详情”的结构。

左侧：

- 候选分组表

右侧：

- 当前选中分组详情
- 分组内候选列表

这样用户不需要频繁切页。

### 3. 筛选区

- 关键词
- 状态
- 质量等级
- 推荐动作
- 业务类型猜测
- session_id
- 是否只看未匹配正式元素

### 4. 分组表列设计

- 候选编码建议
- 候选名称建议
- 业务类型猜测
- 质量等级
- 候选数
- 录制会话数
- 推荐动作
- 已匹配正式元素
- 状态
- 最近更新时间
- 操作

### 5. 分组表的视觉重点

建议将这几列做出层级：

- 第一优先级：候选名称建议、业务类型、质量等级、状态
- 第二优先级：候选数、会话数、已匹配正式元素
- 第三优先级：更新时间

因为审核者最关心的是“这组值不值得处理”。

### 6. 分组操作

每行主操作建议只保留两个：

- 查看候选
- 提升

其余收进更多菜单：

- 合并到已有正式元素
- 批量拒绝组内候选
- 编辑建议编码/名称/语义

### 7. 分组详情面板

右侧详情区分成 4 块：

1. 分组摘要
   - group_key
   - 推荐编码
   - 推荐名称
   - 业务类型猜测
   - 业务域猜测
   - 质量等级
   - 推荐动作

2. 定位概况
   - top locator source
   - top locator type
   - top locator value
   - top role
   - route_scope

3. 风险提示
   - risk tags
   - 为什么低分
   - 是否已有正式元素近似匹配

4. 候选明细表

### 8. 候选明细表列

- locator_type
- locator_value
- role
- route
- step_hit_count
- score
- probe 状态
- 来源 session
- 状态
- 操作

### 9. 候选级操作

- 拒绝
- 标记保留
- 设为主定位器
- 合并到正式元素

注意：

- “标记保留”适合那些当前不提升但值得留着后续观察的候选
- “设为主定位器”应只在提升弹窗里出现，不建议直接裸露成危险操作

### 10. 批量能力

候选治理页必须支持勾选批量：

- 批量拒绝
- 批量标记保留
- 批量合并

建议第一版至少实现：

- 分组级批量拒绝
- 分组级提升

### 11. 提升弹窗设计

这是高频核心弹窗，建议做成中大号弹窗。

分区：

1. 左侧：候选摘要
2. 右侧：正式元素表单

字段：

- element_code
- element_name
- business_type
- business_domain
- 是否关键元素
- testid_value
- qa_value
- route_scope
- 主定位器选择

弹窗底部实时校验提示：

- 编码是否合规
- 编码是否冲突
- 关键元素契约是否满足
- 当前选择的主定位器稳定性是否足够

按钮：

- 取消
- 确认提升

### 12. 合并弹窗设计

弹窗内容：

- 左侧显示当前候选组摘要
- 右侧是“已有正式元素选择器”

选择器支持：

- 搜索 element_code / element_name
- 只显示当前页面元素
- 默认优先推荐同业务类型

底部显示：

- 合并后会新增几条备选定位器
- 是否会覆盖主定位器

建议默认不覆盖主定位器，只新增到 `page_element_locators`。

### 13. 拒绝交互设计

拒绝不能太随意，原因是后续要做回溯分析。

建议：

- 点击拒绝后弹出小弹窗
- `review_note` 必填
- 可快捷选择拒绝原因

快捷原因：

- 重复候选
- 定位不稳定
- 无业务意义
- 页面噪音
- 已合并到其他元素

### 14. 体验重点

- 审核者在 1 分钟内应该能处理完一个常规候选组
- 所以侧边详情必须足够全，不要点来点去才能拼出判断依据
- 推荐动作和风险原因不能只给分数，要给解释

## 八、关键审核流设计

### 1. 录制后治理主路径

1. 录制完成
2. 系统显示候选摘要
3. 点击“去元素列表审核”
4. 进入候选元素 Tab，并自动过滤当前 session
5. 浏览候选分组
6. 对高质量分组执行提升或合并
7. 对噪音候选执行拒绝
8. 返回正式元素 Tab 校验结果

### 2. 正式元素参与后续生成的提示

在正式元素页和提升成功提示中，建议明确告诉用户：

- 审核通过且稳定等级为 high / medium 的正式元素，会参与测试点映射
- low 或 pending 的元素不会进入新映射链路

这样可以把“为什么生成不出来可执行步骤”前置解释掉。

### 3. password_toggle 等特殊语义处理

在提升弹窗和正式元素编辑页中，业务类型必须支持直接选择：

- `password_toggle`
- `metric_label`
- `metric_value`

并提供说明文案。

例如：

- `password_toggle`
  - 用于密码显隐切换按钮，执行时可能需要和 password_input 联合使用
- `metric_label`
  - 适用于“订单数”“销售额”等动态指标名称
- `metric_value`
  - 适用于动态变化的指标数值，不建议直接按 text 固化定位

## 九、设计细节建议

### 1. 文案统一

建议整套页面统一中文：

- 项目
- 页面编码
- 页面名称
- 正式元素
- 候选元素
- 录制历史
- 查看元素
- 开始录制
- 停止录制
- 提升为正式元素
- 合并到已有正式元素
- 批量拒绝

避免中英混杂的字段名直接暴露在页面首层。

### 2. 颜色语义

- 绿色：已通过、已可用、稳定
- 橙色：待审核、治理中、需关注
- 红色：失败、冲突、拒绝、危险动作
- 灰色：草稿、无数据、历史记录

### 3. 图标语义

可选但不强依赖：

- 录制：圆点或摄像头
- 正式元素：立方体 / 图层
- 候选元素：沙漏 / 漏斗
- 回放：播放按钮
- 审核：勾选

### 4. 空状态

每个 Tab 都要有明确空状态，不要只写“暂无数据”。

建议：

- 正式元素为空
  - 还没有正式元素，建议先开始录制并审核候选元素
- 候选元素为空
  - 当前没有待审核候选，可从录制页发起新一轮录制
- 录制历史为空
  - 当前页面还没有录制记录

### 5. 成功反馈

关键操作完成后要给可继续的提示：

- 提升成功：已创建正式元素，可前往正式元素 Tab 查看
- 合并成功：已追加备选定位器，原主定位器未变更
- 拒绝成功：已记录拒绝原因，可在治理日志中追溯

## 十、建议的实现优先级

### P0

- 页面对象列表页治理指标改造
- 元素列表页三 Tab 结构
- 候选分组表 + 右侧详情
- 提升弹窗
- 合并弹窗
- 录制页停止后的结果卡片

### P1

- 正式元素详情抽屉
- 录制历史回放抽屉
- 批量拒绝
- 拒绝原因模板

### P2

- 候选保留态
- 更丰富的治理日志可视化
- 更细致的元素引用分析
- 更强的回放交互

## 十一、最终推荐落地样式

如果只给一句总建议：

- 页面对象列表页做“治理总览”
- 录制页做“候选生产”
- 元素列表页做“正式治理中枢”

不要把审核逻辑散落在录制页、列表页、详情页多处并行维护。用户真正高频工作的地方，应当只有一个，就是元素列表页里的候选元素 Tab。
