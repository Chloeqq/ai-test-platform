# 前端全局字体与视觉体系设计规范

更新时间：2026-05-09

适用范围：AI 质量保障平台全部 React 页面，包括仪表盘、AI 生成工作台、测试资产、用例中心、待审核用例、页面对象、执行与报告、质量治理、系统设置。

关联文件：

- `apps/web-ui-service/frontend/src/styles.css`
- `apps/web-ui-service/frontend/src/App.tsx`
- `apps/web-ui-service/frontend/src/pages/*.tsx`

## 1. 设计目标

本规范用于统一平台全局字体、字号、字重、颜色柔和度、代码区样式和页面信息层级，使平台达到企业级测试管理系统应有的专业感、稳定感和可维护性。

目标：

- 中文不再回退到宋体，所有页面统一使用现代无衬线 UI 字体。
- 字号层级收敛，避免不同模块各自定义导致视觉跳变。
- 字重不过度加粗，降低中文界面的脏感和压迫感。
- 正文、表格、表单、标签、代码块形成稳定的阅读节奏。
- 颜色不使用纯黑和高饱和大面积色，整体更柔和、可信、耐看。
- 通过 CSS token 管理视觉变量，减少 `!important` 和 TSX 内联样式。

## 2. 当前问题诊断

### 2.1 字体族问题

当前已引入 `--font-ui` 和 `--font-mono`，基础方向正确，但仍需确保所有控件、表格、代码区、导航和弹窗继承统一字体。

风险点：

- 表单控件、表格、按钮如果未显式继承，浏览器可能使用系统默认字体。
- TSX 内联样式如果继续硬编码字号和字重，会绕过全局规范。
- 第三方组件或未来引入的组件库需要通过 `.ant-typography` 等入口统一字体。

### 2.2 字号层级过多

当前 CSS 中出现了大量字号：`10px`、`11px`、`12px`、`13px`、`14px`、`15px`、`16px`、`17px`、`18px`、`20px`、`22px`、`24px`、`28px`、`32px`、`34px`、`38px`、`42px`、`44px`。

问题：

- 层级过多会让页面显得“拼装”，而不是一个完整产品。
- `15px`、`17px`、`22px`、`34px` 这类中间值使用过多，容易破坏节奏。
- 不同模块标题大小差异过大，用户会误判信息重要性。

### 2.3 字重过重

当前存在 `750`、`800`、`900` 等高字重，尤其出现在标签、候选卡片标题、序号徽标和状态块中。

问题：

- 中文在 `800/900` 下容易糊成一团。
- 小字号叠加重字重会显得拥挤、噪声高。
- 企业级后台更需要稳定可信，而不是高冲击营销页风格。

### 2.4 颜色和柔和度不统一

当前整体蓝色体系可用，但部分模块有高对比、高饱和、重阴影和强边框并存的问题。

问题：

- 大面积强蓝或高亮状态容易抢走正文注意力。
- 红色危险操作如果过饱和，会制造焦虑。
- 灰色层级不统一会让卡片、表格、分割线显得杂。

### 2.5 代码块和正文边界不足

脚本源码、JSON、YAML、定位器、case id、元素编码需要稳定的等宽字体和浅灰容器。

问题：

- 代码和正文共用普通字体时，可读性差。
- 代码块背景过白会和正文区域混在一起。
- 定位器和编码如果不使用等宽字体，数字和符号难以扫描。

## 3. 设计原则

### 3.1 企业级视觉关键词

- 清晰：优先保证信息可读性，不追求炫技。
- 稳定：字号、字重、颜色尽量少而一致。
- 克制：主色只用于主操作、导航选中和关键状态。
- 柔和：正文不用纯黑，背景不用纯白强对比。
- 可维护：所有基础视觉值 token 化，不让页面各自发明规则。

### 3.2 信息层级原则

页面只允许 5 个主要文字层级：

- 页面标题：用户知道当前在哪。
- 区块标题：用户知道当前看什么信息。
- 正文内容：用户读取业务信息。
- 辅助信息：解释、时间、说明、来源。
- 技术信息：编码、脚本、定位器、日志。

禁止每个模块自定义一套标题大小。

## 4. 字体系统

### 4.1 全局 UI 字体

使用跨平台无衬线字体栈：

```css
--font-ui:
  -apple-system,
  BlinkMacSystemFont,
  "Segoe UI",
  "Microsoft YaHei",
  "Noto Sans SC",
  "PingFang SC",
  Roboto,
  "Helvetica Neue",
  Helvetica,
  Arial,
  sans-serif;
```

适用：

- 页面标题
- 正文
- 表格
- 表单
- 按钮
- 标签
- 弹窗
- 抽屉
- 导航

### 4.2 代码等宽字体

使用跨平台等宽字体栈：

```css
--font-mono:
  "SF Mono",
  Menlo,
  Consolas,
  "Fira Code",
  "Liberation Mono",
  "DejaVu Sans Mono",
  "Courier New",
  monospace;
```

适用：

- `case_id`
- `intent_id`
- 元素编码
- 定位器
- URL
- YAML / JSON / Python 脚本
- 日志
- 错误堆栈
- 版本号

### 4.3 字体渲染

```css
:root {
  -webkit-font-smoothing: antialiased;
  -moz-osx-font-smoothing: grayscale;
}
```

目的：

- macOS 下中文和西文边缘更干净。
- 降低加粗文字毛刺。
- 避免截图中出现旧式宋体观感。

## 5. 字号系统

### 5.1 推荐字号 token

| Token | 数值 | 用途 |
| --- | ---: | --- |
| `--text-xs` | `12px` | 标签、状态、表头、辅助元信息 |
| `--text-sm` | `13px` | 辅助说明、面包屑、空态说明 |
| `--text-md` | `14px` | 正文、表单、表格主体、按钮 |
| `--text-lg` | `16px` | 卡片小标题、表单分组标题 |
| `--title-sm` | `18px` | 区块标题、详情页模块标题 |
| `--title-md` | `20px` | 卡片主标题、重要列表标题 |
| `--title-lg` | `24px` | 页面标题 |
| `--title-xl` | `28px` | 仪表盘重点标题、低频营销型标题 |

建议 CSS：

```css
:root {
  --text-xs: 12px;
  --text-sm: 13px;
  --text-md: 14px;
  --text-lg: 16px;
  --title-sm: 18px;
  --title-md: 20px;
  --title-lg: 24px;
  --title-xl: 28px;
}
```

### 5.2 禁用字号

默认禁用：

- `10px`：过小，不适合后台系统长期阅读。
- `11px`：仅允许极少量图表角标，不用于业务文本。
- `15px`：夹在正文和小标题之间，破坏节奏。
- `17px`：不成体系，改用 `16px` 或 `18px`。
- `22px`：不成体系，改用 `20px` 或 `24px`。
- `32px+`：仅允许登录页、仪表盘 hero 或营销型欢迎区，不用于业务页面。

## 6. 字重系统

### 6.1 推荐字重 token

| Token | 数值 | 用途 |
| --- | ---: | --- |
| `--weight-regular` | `400` | 正文、表格内容、说明 |
| `--weight-medium` | `500` | 轻强调、次级按钮、导航项 |
| `--weight-semibold` | `600` | 表头、字段名、卡片标题 |
| `--weight-bold` | `700` | 页面标题、主标题、关键状态 |

建议 CSS：

```css
:root {
  --weight-regular: 400;
  --weight-medium: 500;
  --weight-semibold: 600;
  --weight-bold: 700;
}
```

### 6.2 禁用字重

默认禁用：

- `800`：除极少数品牌标识外不使用。
- `900`：不用于中文 UI。
- `750`、`650`：非标准中间值，不利于统一维护。
- 大量 `!important` 字重：说明设计 token 没有生效，应回到组件层治理。

### 6.3 模块建议

- 页面标题：`24px / 700`
- 区块标题：`18px / 600`
- 卡片字段名：`12px / 600`
- 卡片字段值：`14px / 600`
- 表头：`12px / 600`
- 表格正文：`14px / 400`
- 标签文字：`12px / 600`
- 主按钮：`14px / 600`
- 次按钮：`14px / 500`
- 代码内容：`13px / 400`

## 7. 行高与字距

### 7.1 行高 token

| Token | 数值 | 用途 |
| --- | ---: | --- |
| `--leading-tight` | `1.35` | 标题 |
| `--leading-normal` | `1.5` | 正文、表格、按钮 |
| `--leading-relaxed` | `1.6` | 长说明、详情描述 |
| `--leading-code` | `1.5` | 代码块、日志 |

### 7.2 字距

原则：

- 中文正文不额外加字距。
- 英文大写标签可用 `0.04em` 到 `0.08em`。
- `case_id`、版本号、状态编码可用 `0.02em`。
- 禁止正文大面积 `letter-spacing`，会影响中文可读性。

## 8. 颜色系统

### 8.1 文本颜色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--text-primary` | `#141414` | 页面标题、强标题 |
| `--text-body` | `#262626` | 正文、主要数据 |
| `--text-secondary` | `#475569` | 字段名、次级正文 |
| `--text-muted` | `#64748b` | 说明、时间、辅助信息 |
| `--text-placeholder` | `#94a3b8` | 占位、空态弱文本 |
| `--text-inverse` | `#ffffff` | 深色背景文字 |

原则：

- 不使用纯黑 `#000000`。
- 正文使用 `#262626`，比纯黑柔和。
- 大段说明使用 `#475569` 或 `#64748b`。
- 禁用低对比灰，例如浅背景上使用 `#b0b0b0`。

### 8.2 背景与边框

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--surface-page` | `#f4f7fb` | 页面底色 |
| `--surface-panel` | `#ffffff` | 主卡片 |
| `--surface-soft` | `#f8fbff` | 次级卡片、表头 |
| `--surface-code` | `#f6f8fa` | 代码块 |
| `--border-soft` | `#e5ecf8` | 卡片边框 |
| `--border-strong` | `#cfd9ea` | 输入框、重要边框 |

原则：

- 页面背景和卡片背景要有轻微层次差。
- 表头背景使用浅蓝灰，不用纯灰。
- 代码块背景使用中性浅灰，不带明显蓝色，避免误认为业务状态。

### 8.3 品牌色与状态色

| 类型 | 背景 | 边框 | 文字 |
| --- | --- | --- | --- |
| 主色 | `#0f4c81` | `#0f4c81` | `#ffffff` |
| 主色浅底 | `#eff6ff` | `#b2ccff` | `#175cd3` |
| 成功 | `#ecfdf3` | `#abefc6` | `#027a48` |
| 警告 | `#fffaeb` | `#fedf89` | `#b54708` |
| 危险 | `#fef2f2` | `#fecaca` | `#b42318` |
| 中性 | `#f8fafc` | `#e2e8f0` | `#475569` |

原则：

- 状态色默认用浅底和深文字，不使用高饱和实心块。
- 实心色只用于主按钮、危险确认按钮、少数核心状态。
- 红色不大面积铺满，只用于危险操作、失败状态和错误提示。

## 9. 组件视觉规范

### 9.1 页面标题区

用途：所有业务页面顶部标题，如用例中心、待审核用例、页面对象、执行记录。

规范：

- 标题：`24px / 700 / #141414`
- 描述：`13px / 400 / #64748b`
- 操作区按钮靠右，主操作在最左或最醒目位置。
- 标题区高度不要过高，避免压缩业务内容。

示例：

```text
用例详情                 [执行用例] [再次生成] [返回列表]
查看单条独立用例的完整信息、步骤、脚本源码和执行历史。
```

### 9.2 侧边导航

规范：

- 一级分组标题：`13px / 700`
- 导航项：`14px / 500`
- 选中态：浅描边或浅背景，不建议文字过粗。
- 折叠按钮文字或符号不应超过 `14px`。

视觉目标：

- 导航是稳定结构，不应抢主内容注意力。
- 当前页面选中态足够清晰即可。

### 9.3 卡片

规范：

- 卡片标题：`18px / 600`
- 字段名：`12px / 600 / #64748b`
- 字段值：`14px / 600 / #141414`
- 边框：`1px solid #e5ecf8`
- 圆角：`12px` 到 `14px`
- 阴影：低透明，不超过 `0 8px 24px rgba(15, 76, 129, 0.06)`

禁止：

- 卡片内所有文字都加粗。
- 卡片阴影过重。
- 字段名和字段值同色同重。

### 9.4 表格

规范：

- 表头：`12px / 600 / #475569`
- 表格正文：`14px / 400 / #262626`
- 编码列：`13px / 400 / --font-mono`
- 行高：`44px` 到 `52px`
- 表头背景：`#f8fbff`
- 分割线：`#edf2fa`

建议：

- 操作列按钮不要全部高亮，只突出当前最常用操作。
- 状态列使用 tag，不使用纯文本。
- 长文本列允许两行截断或悬浮提示。

### 9.5 表单

规范：

- Label：`13px / 600 / #475569`
- 输入内容：`14px / 400 / #262626`
- Placeholder：`14px / 400 / #94a3b8`
- 输入框高度：`36px` 到 `40px`
- Focus：主色浅阴影 `rgba(15, 76, 129, 0.14)`

禁止：

- label 使用 `800`。
- 输入内容使用过小字号。
- 多个表单模块自行定义不同圆角和高度。

### 9.6 按钮

规范：

- 主按钮：`14px / 600`
- 次按钮：`14px / 500`
- 危险按钮：默认描边，确认弹窗中才使用红色实心。
- 按钮高度：`36px` 到 `40px`
- 图标和文字间距：`6px` 到 `8px`

层级：

- Primary：页面主要动作，如执行用例、生成用例、保存。
- Secondary：查看、返回、再次生成、筛选。
- Danger：删除、废弃、驳回。
- Ghost：低频辅助动作。

### 9.7 标签与状态

规范：

- 字号：`12px`
- 字重：`600` 或 `700`
- 圆角：`999px`
- 内边距：`3px 9px` 或 `4px 10px`
- 使用浅底状态色。

建议：

- `已通过`：绿色浅底。
- `待审核`：黄色浅底。
- `已驳回`：红色浅底。
- `未执行`：中性浅底。
- `阻断`：红色或黄色，视严重程度。

禁止：

- 小标签使用 `900`。
- 同一行出现太多实心高饱和标签。

### 9.8 代码块与脚本源码

规范：

- 字体：`--font-mono`
- 字号：`13px`
- 字重：`400`
- 行高：`1.5`
- 背景：`#f6f8fa`
- 边框：`#e1e4e8`
- 内边距：`16px`
- 圆角：`8px`
- 横向滚动优先于强行挤压。

适用：

- YAML 脚本源码
- JSON 响应
- Python / Playwright 代码
- 日志
- 错误堆栈

示例：

```css
.json-block,
.script-source,
.yaml-source,
.json-source {
  font-family: var(--font-mono);
  font-size: var(--text-sm);
  line-height: var(--leading-code);
  background: var(--surface-code);
  border: 1px solid #e1e4e8;
  border-radius: 8px;
  padding: 16px;
  overflow-x: auto;
}
```

### 9.9 空态

规范：

- 标题：`16px / 600 / #141414`
- 描述：`13px / 400 / #64748b`
- 操作按钮：使用 secondary 或 primary，取决于是否推荐立即行动。

空态文案结构：

```text
暂无执行历史
点击上方「执行用例」按钮，开始第一次测试运行。
[立即执行]
```

### 9.10 弹窗与抽屉

规范：

- 标题：`18px / 600`
- 正文：`14px / 400`
- 分组标题：`13px / 600`
- 警告提示：浅黄或浅红底，不使用大面积实心色。
- 底部操作固定，主按钮靠右。

## 10. 典型页面适配建议

### 10.1 用例详情页

现状：整体层级较清晰，代码块已改为等宽字体。

建议：

- `case-step-index` 从 `900` 降到 `700`。
- `case-action-badge` 从 `800` 降到 `600`。
- 基本信息字段名保持 `12px / 600`，字段值保持 `14px / 600`。
- 脚本源码保持 `13px / 400`。

### 10.2 用例中心列表页

建议：

- 用例标题：`14px / 600`
- 用例编码：`13px / 400 / --font-mono`
- 来源资产：`14px / 500`，链接色不宜过蓝。
- 状态标签：`12px / 600`
- 操作按钮：以 `执行` 为主，详情、报告弱化。

### 10.3 待审核用例页

建议：

- 审核状态标签使用浅底状态色。
- 可生成状态不使用过重图标，使用文本加轻量色块。
- 表格内测试点标题不超过 `14px / 600`。
- 批量操作条使用 `13px`，避免喧宾夺主。

### 10.4 AI 生成工作台

这是当前最需要治理的模块。

问题：

- 存在多层 `.aiw-page` 覆盖。
- 标题先后出现 `44px`、`28px`、`24px !important`。
- 候选卡片存在 `18px / 800` 和 TSX 内联样式。

建议：

- 普通业务态页面标题统一 `24px / 700`。
- 只有欢迎态或空工作台 hero 可使用 `28px`。
- 候选标题统一 `16px / 600` 或 `18px / 600`。
- 移除 TSX 内联 `fontSize/fontWeight`，改成 CSS class。
- 删除重复的 `.aiw-page` 覆盖段，保留一套最终规则。

### 10.5 页面对象管理

建议：

- 页面对象列表和元素治理属于高密度管理页，使用更克制的字号。
- 表格主体：`14px / 400`
- 元素编码和定位器：`13px / --font-mono`
- 候选质量标签：`12px / 600`
- 风险提示：浅黄或浅红底，避免全红。

### 10.6 执行与报告

建议：

- 报告结果数字可使用 `24px / 700`。
- 普通指标卡不超过 `20px / 700`。
- 日志、stderr、stdout 一律使用代码块规范。
- 失败原因标题使用 `16px / 600`，正文使用 `14px / 400`。

### 10.7 仪表盘

建议：

- 仪表盘允许更强视觉，但仍应克制。
- Hero 标题最大 `28px`，除非登录页或营销页。

## 12. 禁用清单

开发时默认禁止：

- 新增 `font-family` 硬编码，必须使用 `--font-ui` 或 `--font-mono`。
- 新增 `font-size: 10px`、`11px`、`15px`、`17px`、`22px`。
- 新增 `font-weight: 800`、`900`、`750`、`650`。
- 在 TSX 中写 `fontSize`、`fontWeight`、`fontFamily`。
- 用 `!important` 解决普通样式优先级问题。
- 大面积使用纯黑 `#000`、纯红、纯蓝实心背景。
- 代码、日志、编码、定位器使用普通字体。

允许例外：

- 登录页或仪表盘 hero 可使用 `32px+`，但必须有明确视觉目标。
- 图表极小角标可使用 `11px`，但不得用于业务正文。
- 品牌 Logo 可使用特殊字重。

## 13. 迁移计划

### 阶段 1：全局 token 补齐

目标：

- 在 `:root` 补齐字号、字重、颜色、行高 token。
- 确保 `body/button/input/select/textarea/table` 使用统一字体。
- 确保 `.mono/.json-block/code/pre` 使用统一等宽字体。

验收：

- 中文不出现宋体观感。
- 表单、表格、按钮字体一致。
- 脚本源码和日志可读性明显提升。

### 阶段 2：高风险模块清理

优先模块：

- AI 生成工作台
- 候选测试点卡片
- 用例详情页徽标和标签
- 页面对象候选治理页

动作：

- 删除 TSX 内联字体样式。
- 合并重复 `.aiw-page` 覆盖规则。
- 将 `800/900` 降为 `600/700`。
- 将 `44px` 普通业务标题降为 `24px` 或 `28px`。

### 阶段 3：组件级规范固化

动作：

- 建立 `PageHeader`、`DataTable`、`StatusTag`、`CodeBlock` 等稳定组件样式。
- 新页面只复用组件，不再自定义字体层级。
- 将 lint 或 code review 规则加入前端治理清单。

## 14. 验收清单

每个页面上线前检查：

- 页面标题是否为 `24px / 700`，没有无意义放大。
- 区块标题是否为 `18px / 600`。
- 正文、表单、表格主体是否为 `14px / 400`。
- 辅助说明是否为 `13px / 400`。
- 标签和表头是否为 `12px / 600`，没有 `900`。
- 代码和日志是否使用 `--font-mono`。
- 是否存在 TSX 内联 `fontSize/fontWeight/fontFamily`。
- 是否新增了 `!important`。
- 状态色是否使用浅底、深文字。
- 页面整体是否能在 125% 浏览器缩放下保持可读。

## 15. 推荐最终视觉状态

平台最终应呈现为：

- 一致的无衬线中文黑体观感。
- 标题清楚但不夸张。
- 正文柔和、长时间阅读不疲劳。
- 表格密度适中，信息一眼能扫。
- 状态标签清晰但不过度抢眼。
- 代码块有明确边界，适合阅读 YAML、Python、JSON。
- 各模块像同一个产品，而不是多个页面拼接在一起。

## 17. 企业级颜色柔和度规范

### 17.1 柔和度目标

平台属于测试管理和质量工程工具，视觉气质应是“可信、冷静、稳定、清晰”，而不是“营销、游戏化、强刺激”。

因此颜色策略为：

- 页面底色使用浅蓝灰，减少纯白眩光。
- 卡片使用白色或近白色，保留清晰层次。
- 主色只用于关键动作和选中态。
- 状态色统一采用浅底深字。
- 危险色只在用户需要警觉时出现，不作为装饰色。

### 17.2 色彩使用比例

建议页面整体色彩比例：

| 类型 | 占比 | 说明 |
| --- | ---: | --- |
| 中性背景与卡片 | 70% | 页面底色、卡片、表格、输入框 |
| 文字与边框 | 20% | 正文、标题、分割线、说明 |
| 品牌主色 | 6% | 主按钮、链接、选中态 |
| 状态色 | 4% | 成功、警告、危险、阻断 |

禁止：

- 大面积主色铺底。
- 多种高饱和状态色同时出现。
- 用红色表达普通提醒。
- 用纯黑作为正文色。

### 17.3 阴影与边框柔和度

企业后台默认使用“边框为主、阴影为辅”的层级方式。

推荐：

```css
--shadow-panel: 0 8px 24px rgba(15, 76, 129, 0.06);
--shadow-popover: 0 12px 32px rgba(15, 23, 42, 0.12);
--shadow-focus: 0 0 0 3px rgba(15, 76, 129, 0.14);
```

使用原则：

- 普通卡片：轻边框 + 极轻阴影。
- 弹窗/抽屉：可使用中等阴影以脱离页面。
- 表格行：不使用阴影，仅使用 hover 背景。
- Focus：使用柔和主色外环，不使用刺眼实线。

## 19. 视觉走查流程

每次新增或重构页面时，必须按以下顺序走查：

1. 检查页面是否继承 `--font-ui`，代码区是否使用 `--font-mono`。
2. 检查页面标题、区块标题、正文、说明、标签是否落在指定字号 token 内。
3. 检查是否存在 `800/900/750/650` 等非规范字重。
4. 检查状态色是否为浅底深字，危险色是否过量。
5. 检查代码块、URL、locator、case_id 是否使用等宽字体。
6. 检查表格在 125% 浏览器缩放下是否仍可读。
7. 检查页面是否有多套互相覆盖的样式规则。
8. 检查 TSX 中是否新增 `fontSize/fontWeight/fontFamily` 内联样式。

## 20. 设计与开发协作规则

### 20.1 设计侧交付要求

设计稿或产品说明必须标明：

- 页面标题层级。
- 主要状态标签类型。
- 是否包含代码/日志/定位器区域。
- 是否存在危险操作。
- 是否存在高密度表格。

### 20.2 前端开发要求

前端实现必须：

- 优先复用全局 token，不新增孤立色值。
- 优先复用组件类名，不在 TSX 写字体内联样式。
- 新增页面前先判断属于列表页、详情页、工作台页还是报告页。
- 新增状态前先复用已有状态色，不随意增加新的红黄绿。

### 20.3 Code Review 要求

评审时出现以下情况需要退回修改：

- 中文页面出现宋体观感。
- 同一页面出现超过 5 个正文字号。
- 普通业务标题超过 `28px`。
- 小标签使用 `800/900`。
- 脚本、日志、locator 没有使用等宽字体。
- 大面积使用高饱和红色、蓝色或绿色。

## 21. 下一步落地建议

建议按以下优先级实施：

1. 先把 `styles.css` 的 `:root` token 补齐，确保全局视觉变量完整。
2. 再治理 AI 生成工作台中重复 `.aiw-page` 和 TSX 内联字体样式。
3. 然后统一用例中心、待审核用例、页面对象这三个高频管理页的表格和标签。
4. 最后统一详情页中的代码块、步骤表格、执行历史和空态组件。

完成后，平台的视觉会从“功能拼装完成”提升到“企业级可演示、可交付、可持续维护”的状态。
