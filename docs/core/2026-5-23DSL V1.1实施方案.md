# DSL V1.1 生成器端关键字段补齐实施计划

## Summary

在生成器端补齐 DSL V1.1 最小可用契约，让新生成的 `script_code` 自动具备去重、数据治理和可执行断言能力。只改生成链路，不手动改 YAML、不改数据库历史数据、不写任何账号密码默认值。

核心目标：

- `requirement.source_asset_id + requirement.intent_id` 稳定生成，用于去重。
- `execution.selected_intent_ids` 稳定生成，用于覆盖校验。
- `data + execution.variables` 从测试点步骤已有输入值提升生成。
- 顶层 `assertions` 稳定生成，`expected_result` 只作为说明，不作为通过依据。

## Key Changes

- 在 `/Users/bettyhuang/PycharmProjects/ai-test-platform/apps/web-ui-service/app/services/workbench_generation_compiler/runtime/generate_pipeline.py` 增加 DSL V1.1 enrichment：
  - 在 `_format_product_case_yaml()` 最后统一补齐 V1.1 字段。
  - 保留 `script_code` 为唯一事实源，新生成 YAML 写入 DB 后由用例中心和 runner 读取。
  - 不修改被测地址，继续保留 `http://localhost:5174/#/login`。

- 身份字段生成规则：
  - `requirement.intent_id` 来自当前生成的 `selected_intent_ids[0]`。
  - `requirement.source_asset_id` 来自 `selected_candidate.source_asset_id`，缺失时从 candidate snapshot 兜底。
  - `execution.selected_intent_ids` 必须包含当前 intent，不能为空。
  - 如果当前 intent 或 source asset 无法解析，生成失败，不生成半成品用例。

- 数据字段生成规则：
  - 只从测试点/编译步骤中已有的 `input` 步骤 `value` 提升数据。
  - 禁止写入任何代码默认账号密码，例如 `admin/macro`、`test001/123456`。
  - `login.username_input` 映射为 `data.username` 和 `execution.variables.login_username`。
  - `login.password_input` 映射为 `data.password` 和 `execution.variables.login_password`。
  - 其他输入元素按 `{element_code 去掉 _input 后缀}` 生成 data key，变量名为 `{page}_{data_key}`。
  - 步骤中的 literal value 改写为 `{{variable_name}}`。
  - 如果 input 步骤没有 value，返回 422，错误码建议为 `dsl_v1_1_missing_input_data`。

- 断言字段生成规则：
  - 优先保留测试点或编译步骤中已有的 `assert_*`。
  - 若 `execution.steps` 中已有 `assert_*`，迁移/复制到顶层 `assertions`，并避免重复。
  - 登录成功类用例可从页面对象 `home_menu` 生成 `assert_visible`。
  - 若 AI 自动化用例无法生成任何可执行断言，返回 422，错误码建议为 `dsl_v1_1_missing_executable_assertion`。
  - `expected_result` 不参与通过/失败判定。
