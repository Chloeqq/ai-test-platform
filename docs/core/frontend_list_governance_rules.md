# 前端列表治理规范

## 目标

统一平台内所有列表页的基础体验，避免不同页面各自实现筛选、分页、删除和批量操作，降低测试资产、用例、页面对象等治理数据的使用成本。

## 通用结构

所有管理型列表默认采用以下结构：

1. 页面标题区：说明当前列表的业务对象和关键操作。
2. 筛选区：承载项目、关键词、状态等页面级筛选。
3. 表格区：承载数据明细，枚举列可在表头内嵌列筛选。
4. 批量操作区：用户勾选数据后展示批量删除等操作。
5. 分页区：展示总数、当前范围、上一页、下一页和每页条数。

## 筛选规范

页面级筛选用于影响整张表的数据范围，例如项目、关键词、页面、状态。

列级筛选用于枚举字段，例如类型、优先级、状态、来源。列级筛选应嵌入表头，不额外占用页面高度。筛选生效后，表头筛选控件需要有高亮状态，并支持一键切回“全部”。

常见枚举中文化：

- 测试点类型：功能、异常、安全、边界、格式、交互异常。
- 优先级：P0、P1、P2，使用高饱和颜色区分。
- 来源：AI 自动生成、手动创建、手动输入。
- 状态：待审核、已通过、已驳回、已阻断、草稿。

## 分页规范

所有列表必须提供分页。默认每页 10 条，允许切换 10、20、50 条。

分页区展示：

- 总条数。
- 当前展示范围，例如“第 1-10 条”。
- 当前页与总页数。
- 上一页、下一页。
- 每页条数选择。

## 删除规范

所有管理型列表必须提供单条删除和批量删除能力。

删除要求：

- 单条删除放在行操作列。
- 批量删除通过勾选行后展示。
- 删除前必须二次确认。
- 删除文案必须说明删除对象、影响范围和是否不可恢复。
- 没有后端删除能力的列表，不允许放置假按钮，应在接口补齐后接入。

## 第一阶段接入范围

第一阶段先抽通用前端控件，并优先接入以下页面：

- 测试点资产详情页：测试点明细表支持类型、优先级列筛选和分页。
- 测试点资产详情页：测试点明细表支持单条删除和批量删除，删除后更新资产内完整测试点数组。
- 测试点资产列表：复用已有删除和批量删除能力，逐步迁移到统一控件。
- 页面对象列表、页面对象元素列表、录制历史列表：已有物理删除能力，后续按统一控件改造。

## 已有删除能力清单

可以直接接入统一删除交互的列表：

- 测试点资产列表：已有单条删除和批量删除接口。
- 测试点资产详情页测试点明细：可通过资产更新接口提交删除后的完整测试点数组。
- 页面对象列表：已有单条删除接口，批量删除由前端循环调用现有删除接口。
- 页面对象正式元素列表：已有批量物理删除接口。
- 页面对象候选分组列表：已有批量物理删除接口。
- 页面对象候选明细列表：已有批量物理删除接口。
- 页面对象录制历史列表：已有批量物理删除接口。
- 用例中心、待审核用例：后端已有 `/api/test-cases/batch/delete`，前端需要补 API 封装和统一删除交互。
- 项目列表：已有单条删除接口，批量删除需要补后端接口或按业务确认是否允许。

## 后续接入清单

需要补齐删除接口后再接入的列表：

- 用例版本列表。
- 项目字典、标签、数据模板等配置型列表。

只读报告类列表默认不提供删除；如业务确认需要清理历史数据，应先补充归档或清理接口。
