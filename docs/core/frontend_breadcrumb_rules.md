# 前端面包屑规范与落地方案

## 背景

当前 React 前端的面包屑由少量页面手写，存在覆盖不完整、样式不统一、不可点击、命名与侧边栏不一致等问题。面包屑应从页面局部装饰升级为全局信息架构能力，帮助用户确认当前位置、快速回到父级任务域，并保持和左侧导航一致。

## 设计原则

1. 面包屑由全局路由元数据生成，业务页面不再手写。
2. 层级控制在三级以内：一级业务域 / 二级模块 / 当前页面。
3. 一级业务域必须与侧边栏分组一致。
4. 二级模块优先与侧边栏菜单项一致。
5. 当前页与页面 H1 保持语义一致，详情页可显示资源标识。
6. 前两级可点击，最后一级不可点击。
7. 动态详情页返回父级时保留关键上下文，例如 `project` 查询参数。
8. 使用语义化结构：`nav[aria-label="面包屑"] > ol > li`。

## 标准层级

| 页面类型 | 面包屑示例 |
| --- | --- |
| 仪表盘 | 仪表盘 / 总览 |
| AI 生成工作台 | AI 生成 / 生成工作台 |
| 生成历史 | AI 生成 / 生成历史 |
| 用例中心 | 测试资产 / 用例中心 |
| 用例详情 | 测试资产 / 用例中心 / 用例详情 |
| 测试点资产详情 | 测试资产 / 测试点资产 / 测试点资产详情 |
| 页面对象元素详情 | 测试资产 / 页面对象 / 元素详情 |
| 录制回放详情 | 测试资产 / 页面对象 / 录制回放详情 |
| 执行报告详情 | 执行与报告 / 结果总览 / 执行报告详情 |
| 质量门禁 | 质量治理 / 质量门禁 |
| 项目管理 | 系统设置 / 项目管理 |

## 命名统一

| 导航分组 | 统一命名 |
| --- | --- |
| AI 生成 | 生成工作台、生成历史、提示词管理 |
| 测试资产 | 用例中心、待审核用例、用例版本、标签治理、测试点资产、页面对象、接口契约、数据模板 |
| 执行与报告 | 执行计划、执行记录、结果总览、失败分析、上下文、性能分析、Allure 报告 |
| 质量治理 | Flaky 分析、失败聚类、趋势分析、质量门禁、缺陷看板 |
| 系统设置 | 项目管理、源码管理、任务调度、环境管理、节点管理、集成配置、权限角色 |

## 实施步骤

1. 新增统一 `Breadcrumbs` 组件。
2. 在组件内维护路由元数据表，使用当前路径匹配生成面包屑。
3. 将组件挂载到 `GlobalNavLayout` 的内容区顶部。
4. 删除页面中手写的 `.breadcrumb` 和 `.asset-breadcrumb`。
5. 补充统一样式 `.platform-breadcrumbs`。
6. 跑前端构建，确保所有路由可编译。

## 验收标准

1. 登录后的所有主页面都有统一面包屑。
2. 面包屑一级与侧边栏分组一致。
3. 列表页、详情页、工具页的层级不超过三级。
4. 最后一项为当前页且不可点击。
5. 父级项可点击返回。
6. 页面内不再出现局部手写 `.breadcrumb` / `.asset-breadcrumb`。
