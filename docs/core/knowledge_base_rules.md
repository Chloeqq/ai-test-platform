# 知识库规范

这份文档定义 Dify 和平台共同依赖的知识库边界，避免检索层和后端规则层各自猜测。

## 1. 目标

- 让每个项目的私有知识可检索、可追踪、可版本化。
- 知识库只提供“已确认事实”，不提供通用兜底答案。
- 检索结果只能作为输入证据，不能替代显式规则校验。

## 2. 知识库建议拆分

- 按 `project` 拆分
- 按 `page` 或页面域标签分类
- 至少区分以下内容：
  - 页面对象
  - 元素别名
  - 业务规则
  - 成功样本
  - 失败样本
  - 质量门禁说明

## 3. 检索约束

- 查询必须包含 `project`，必要时再带 `page`
- 不允许跨项目自由混搜
- 不允许把“看起来像”的结果当成正确结果
- 检索命中的内容必须能映射到明确的页面、元素或规则

## 4. 写入规范

- 页面对象和元素规则优先作为结构化知识写入
- 业务规则应尽量短句化、原子化
- 一个事实只写一个位置，避免重复解释
- 更新知识后要同步提示词或校验逻辑

## 5. 不建议写入的内容

- 模糊说明
- 未确认的推断
- 纯自由文本总结
- 会与后端硬校验冲突的“建议写法”

## 6. 与平台后端的关系

- `shared_backend/element_binding.py` 负责元素别名解析
- `shared_backend/intent_mapping.py` 负责显式步骤映射
- `shared_backend/execution_compiler.py` 负责执行约束
- 知识库只补充事实，不替代这些模块的硬规则
