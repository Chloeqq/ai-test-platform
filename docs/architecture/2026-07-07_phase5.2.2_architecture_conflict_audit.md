# Phase 5.2.2 Dashboard 与 Gate 架构冲突审计

日期：2026-07-07

## 1. 代码职责边界

依赖图：

```
quality_dashboard_service.py
    ├── import _build_quality_report  ← fallback only
    └── import workbench_state_store  ← paths

workbench_asset_views.py (Gate)
    └── (no dashboard reference)

workbench_quality_gate_summary_service.py
    └── 独立领域 — execution gate history summary, NOT asset quality
```

| 模块 | 职责 | 合理 | 建议 |
|------|------|------|------|
| _build_quality_report | 唯一质量计算源 | ✅ | 保持 |
| get_quality_gate_violations | Gate 规则引擎 | ✅ | 保持 |
| check_*_gate | Gate 阻断入口 | ✅ | 保持 |
| quality_dashboard_service | 只读聚合 + 趋势 | ✅ | 保持 |
| quality_gate_summary_service | 执行历史 Gate 事件汇总 | ✅ | 独立领域 |

**是否存在冲突：NO** — 单向依赖，无循环。

## 2. Quality Report 单一来源

_build_quality_report 同时被 Gate (计算 + 阻断) 和 Dashboard (fallback) 调用。保持方案 A，不拆分。

## 3. Gate 与 Dashboard 数据关系

Gate = 计算层，Dashboard = 展示聚合层。Dashboard 不自己计算质量，不与 Gate 共享 Engine。

## 4. 重复计算风险

无风险。Dashboard fallback 调用同一 _build_quality_report。

## 5. Snapshot 设计

推荐方案 B：保存完整 quality_report 字段（当前 14 字段已覆盖）。

## 6. batch_review Snapshot 缺失

P2 — review_status 不改变 quality 指标，可延期。

## 7. 最终架构

当前架构合理，无需调整。

```
Asset
  ├── Quality Report (_build_quality_report)
  │     ├── Gate (violations → 阻断)      ← 执行层
  │     └── Snapshot (append JSONL)        ← 持久层
  │           └── Dashboard (聚合)         ← 展示层
  └── Execution Gate History               ← 独立领域
```

## 结论

- 是否存在冲突：NO
- 冲突等级：无
- 必须修改项：无
- 可以延期项：P2 batch_review snapshot, 字段常量化
- 推荐下一阶段：Phase 5.3 Frontend 或 Phase 6 架构整理
