# Phase 5.4：AI 测试质量评估中心设计

## 0. 定位与边界

### 不是"AI 模型评测平台"

不做 OpenA-Evals / LangSmith / Promptfoo 类的通用 LLM 评估工具。

### 是"AI 测试质量评估中心"（AI Quality Evaluation Center）

**评测对象**：AI 生成的软件测试资产（测试用例、测试脚本、断言、测试数据）。

**核心命题**：当 AI 替你生成测试用例时，你怎么知道它生成的质量好不好？

**在 ATP 闭环中的位置**：

```
需求输入
  ↓
AI Agent 生成测试用例
  ↓
DSL 编译器（44 个编译期检查点，拦截不可执行的结构）
  ↓
Quality Gate（17 条规则 → PASS / REVIEW / REJECT）
  ↓
Playwright + Pytest 执行
  ↓
┌─────────────────────────────────────────────┐
│  AI Test Quality Evaluation Center  ← 新增   │
│                                              │
│  测试覆盖率分 (Coverage Score)               │
│  断言质量分 (Assertion Quality Score)        │
│  可执行性分 (Executability Score)            │
│  输出一致性分 (Consistency Score)            │
│  抗扰动性分   (Robustness Score)             │
│  AI 幻觉风险  (Hallucination Risk)          │
│                                              │
│  → 综合质量评分 + 回归趋势报告               │
└─────────────────────────────────────────────┘
  ↓
反馈到 Agent / Prompt / 规则优化
```

### 与 Quality Gate 的分工

| | Quality Gate（已有） | Evaluation Center（新增） |
|---|---|---|
| **作用** | 卡点：能不能发布？ | 度量：质量有多好？ |
| **输出** | PASS / REVIEW / REJECT | 0-100 多维度评分 |
| **粒度** | 整条用例 | 用例 + 每个断言 + 每个步骤 |
| **时机** | 编译期 + 执行后 | 执行后（需要执行结果） |
| **类比** | CI 门禁 | 测试报告 + 趋势分析 |

## 1. MVP 范围（3 天）

| JD 要求 | 原方案（偏了） | 修正后 |
|---------|--------------|--------|
| 评测数据集管理 | 通用 QA 对数据集 | **测试资产评测数据集**（用例+预期断言+预期覆盖场景） |
| 输出一致性 | 测 LLM 通用回答 | **同一需求多次 AI 生成，用例质量是否稳定** |
| 幻觉识别 | 测物理常识 | **检测 AI 生成用例中的假元素、假页面、假数据** |
| 提示词鲁棒性 | 错别字扰动 | **需求文本微调后，生成用例是否保持相同覆盖** |
| 批量推理验证 | 批量子纠缠问题 | **10 条需求批量生成 → 批量评分 → 排名** |
| 质量度量体系 | 无 | **Coverage / Assertion / Executability 三维 ATP 特有指标** |
| 回归报告 | 无 | **Agent 版本 / 模型版本 / 规则版本升级前后质量对比** |

不做的：偏见与公平性、多模态测试、vLLM/Triton 对接（面试时讲后续规划）。

## 2. 数据模型

### 2.1 评测数据集 `quality_eval_datasets`

```sql
CREATE TABLE quality_eval_datasets (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    dataset_id      VARCHAR(64) UNIQUE NOT NULL,
    project_code    VARCHAR(20) NOT NULL DEFAULT 'atp',
    name            VARCHAR(255) NOT NULL,
    description     TEXT DEFAULT '',
    task_type       VARCHAR(50) NOT NULL,
        -- 'test_case_generation' | 'script_generation' | 'assertion_generation' | 'data_generation'
    eval_dimensions JSON DEFAULT '[]',
        -- 本次评测启用的维度列表，如 ["coverage","assertion_quality","executability","consistency","robustness","hallucination"]
    item_count      INTEGER DEFAULT 0,
    version         INTEGER DEFAULT 1,
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 2.2 评测条目 `quality_eval_items`

```sql
CREATE TABLE quality_eval_items (
    id                  INTEGER PRIMARY KEY AUTOINCREMENT,
    item_id             VARCHAR(64) UNIQUE NOT NULL,
    dataset_id          VARCHAR(64) NOT NULL,

    -- 输入：给 AI 的需求描述
    requirement_text    TEXT NOT NULL,
    -- 可选：附加上下文（页面 URL、业务规则等）
    context_json        JSON DEFAULT '{}',

    -- 预期输出的结构标准（不是"正确答案"，而是"应该覆盖什么"）
    expected_coverage   JSON DEFAULT '[]',
        -- ["正常登录", "密码错误", "验证码过期", "账号锁定"]
    expected_assertions JSON DEFAULT '[]',
        -- [{"type":"url_assert","target":"/dashboard"}, {"type":"visible","target":"欢迎文本"}]
    expected_page_codes JSON DEFAULT '[]',
        -- 预期涉及的页面对象

    -- 扰动版需求（鲁棒性测试用）
    perturbed_requirement TEXT DEFAULT '',

    -- 已知缺陷标签（金标准）
    known_issues        JSON DEFAULT '[]',
        -- ["弱断言", "缺少异常场景", "元素定位不准确"]

    category            VARCHAR(50) DEFAULT '',
    meta_data           JSON DEFAULT '{}',
    created_at          DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (dataset_id) REFERENCES quality_eval_datasets(dataset_id)
);
```

### 2.3 评测运行 `quality_eval_runs`

```sql
CREATE TABLE quality_eval_runs (

        -- Quality Gate 规则集版本

    status              VARCHAR(20) DEFAULT 'pending',
    total_items         INTEGER DEFAULT 0,
    completed_items     INTEGER DEFAULT 0,

    -- 综合评分
    overall_score       REAL DEFAULT 0,
    -- 分维度评分
    coverage_score      REAL DEFAULT 0,
    assertion_score     REAL DEFAULT 0,
    executability_score REAL DEFAULT 0,
    consistency_score   REAL DEFAULT 0,
    robustness_score    REAL DEFAULT 0,
    hallucination_risk  REAL DEFAULT 0,

    summary_json        JSON DEFAULT '{}',
    created_at          DATETIME DEFAULT CURRENT_TIMESTAMP,
    finished_at         DATETIME,
    FOREIGN KEY (dataset_id) REFERENCES quality_eval_datasets(dataset_id)
```

### 2.4 评测结果 `quality_eval_results`

```sql
CREATE TABLE quality_eval_results (
    id                  INTEGER PRIMARY KEY AUTOINCREMENT,
    result_id           VARCHAR(64) UNIQUE NOT NULL,
    run_id              VARCHAR(64) NOT NULL,
    item_id             VARCHAR(64) NOT NULL,

    -- 被测输出：AI 生成的测试用例内容
    generated_case_json JSON DEFAULT '{}',
        -- {case_id, name, steps, assertions, preconditions, ...}
    generated_script    TEXT DEFAULT '',
        -- AI 生成的 Playwright 脚本

    -- ======== ATP 特有评分维度 ========

    -- 1. 测试覆盖率分（0-100）
    coverage_score      REAL DEFAULT 0,
    coverage_detail     JSON DEFAULT '{}',
        -- {covered_scenarios:[], missed_scenarios:[], coverage_rate:0.75}

    -- 2. 断言质量分（0-100）
    assertion_score     REAL DEFAULT 0,
    assertion_detail    JSON DEFAULT '{}',
        -- {total_assertions:3, weak_assertions:1, strong_assertions:2, missing_assertions:["url_check"]}

    -- 3. 可执行性分（0-100）
    executability_score REAL DEFAULT 0,
    executability_detail JSON DEFAULT '{}',
        -- {compile_passed:true, execution_passed:false, failed_step:3,
        --  gate_decision:"REVIEW", gate_rule_hits:["rule_006","rule_008"]}

    -- ======== JD 通用维度 ========

    -- 4. 一致性（多次生成对比）
    consistency_runs    JSON DEFAULT '[]',
        -- [{run:1, case_json:{...}}, {run:2, case_json:{...}}]
    consistency_score   REAL DEFAULT 0,

    -- 5. 鲁棒性（扰动需求对比）
    perturbed_output    JSON DEFAULT '{}',
    robustness_score    REAL DEFAULT 0,

    -- 6. 幻觉检测
    hallucination_flags JSON DEFAULT '[]',
        -- ["假页面:old_login_page", "不存在的元素:#submit-btn-v2", "数据捏造:测试手机号13800000000重复"]
    hallucination_score REAL DEFAULT 0,

    -- 综合得分
    weighted_score      REAL DEFAULT 0,

    -- 元信息
    latency_ms          INTEGER DEFAULT 0,
    token_count         INTEGER DEFAULT 0,
    error_message       TEXT DEFAULT '',
    created_at          DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (run_id) REFERENCES quality_eval_runs(run_id),
    FOREIGN KEY (item_id) REFERENCES quality_eval_items(item_id)
);
```

## 3. 评估引擎设计（核心）

### 3.1 评估器架构

```python
# evaluator.py — 策略模式，可插拔

from abc import ABC, abstractmethod

class QualityEvaluator(ABC):
    """评估器基类"""
    evaluator_type: str  # "rule_based" | "keyword" | "embedding" | "llm_judge"

    @abstractmethod
    def evaluate(self, item: EvalItem, output: GeneratedCase) -> EvalScores:
        ...


class CoverageEvaluator(QualityEvaluator):
    """
    测试覆盖率评估器
    evaluator_type = "rule_based"

    逻辑：
    1. 从 item.expected_coverage 读取预期覆盖场景
    2. 从 output.generated_case_json 提取 AI 实际覆盖的场景
    3. 计算：covered ∩ expected / expected
    4. 额外加分：AI 自主发现的边界场景（不在预期中但合理）
    """

class AssertionQualityEvaluator(QualityEvaluator):
    """
    断言质量评估器
    evaluator_type = "rule_based" + 复用 Quality Gate 规则

    逻辑：
    1. 统计断言总数
    2. 分类：强断言（url/visible/text/attribute）vs 弱断言（title/not_empty）
    3. 命中 Quality Gate 规则的断言问题（rule_003/rule_008/rule_009）
    4. 分数 = (强断言数 * 权重 + 规则命中扣分) / 归一化
    """

class ExecutabilityEvaluator(QualityEvaluator):
    """
    可执行性评估器
    evaluator_type = "rule_based" + 真实执行结果

    逻辑：
    1. DSL 编译是否通过（0 或 1）
    2. Quality Gate 决策（PASS=满分, REVIEW=扣分, REJECT=零分）
    3. 实际执行结果（全部通过 / 部分失败 / 全部失败）
    4. 失败步骤的归因（元素定位 / 断言失败 / 超时）
    """

class ConsistencyEvaluator(QualityEvaluator):
    """
    输出一致性评估器
    evaluator_type = "embedding"

    逻辑：
    1. 同一需求，调用 Agent N 次（N=3）
    2. 提取每次生成用例的结构化特征向量：
       - 场景数、步骤数、断言数、涉及页面数
    3. 两两计算余弦相似度
    4. 分数 = 平均相似度 * 100
    """

class RobustnessEvaluator(QualityEvaluator):
    """
    需求鲁棒性评估器
    evaluator_type = "embedding"

    逻辑：
    1. 原需求 → 生成用例 A
    2. 扰动需求 → 生成用例 B
    3. 对比 A 和 B 的覆盖场景差异
    4. 分数 = 100 - diff_rate * 100
       （差异越小 → 对输入扰动越鲁棒）
    """

class HallucinationEvaluator(QualityEvaluator):
    """
    AI 幻觉检测器
    evaluator_type = "rule_based" + Quality Gate rule_016（AI 幻觉检测规则）

    逻辑：
    1. 提取生成用例中引用的所有页面/元素/数据
    2. 与 PageObject 资产库对比
    3. 不存在的页面 → "假页面"
    4. 不存在的元素 → "幻觉元素"
    5. 数据库中无对应记录的数据 → "数据捏造"
    6. 命中 rule_016 → 扣分
    """

class LLMJudgeEvaluator(QualityEvaluator):
    """
    LLM-as-Judge 评估器（预留接口，MVP 不实现）
    evaluator_type = "llm_judge"

    用于语义级评判：当 rule_based 和 embedding 无法判断时，
    调用另一个 LLM 来评判 AI 生成的用例质量。
    例如："这个测试用例的断言是否足够验证登录成功的语义？"
    """
```

### 3.2 加权综合评分

```python
DEFAULT_WEIGHTS = {
    "coverage":       0.25,   # 覆盖了多少场景
    "assertion":      0.25,   # 断言质量
    "executability":  0.25,   # 能不能跑
    "consistency":    0.10,   # 稳不稳定
    "robustness":     0.10,   # 怕不怕扰动
    "hallucination":  0.05,   # 有没有编造
}

def compute_weighted_score(scores: dict, weights: dict = None) -> float:
    """加权综合分 = Σ(score_i × weight_i)"""
    weights = weights or DEFAULT_WEIGHTS
    return sum(scores.get(k, 0) * w for k, w in weights.items())
```

## 8. 面试话术（3 分钟版）

> "做完 AI 测试用例生成之后，我设计了一个 AI 测试质量评估中心。核心问题是：**当 AI 替你生成测试用例时，你怎么知道它生成的质量好不好？能不能上线？**
>
> "我设计了 6 个评估维度。前 3 个是我的平台特有的——**测试覆盖率**（AI 有没有覆盖所有应该测的场景）、**断言质量**（断言够不够强、能不能真正捕获 bug）、**可执行性**（生成的脚本能不能在 Playwright 里跑通）。这 3 个维度的评分逻辑直接复用了我已有的 Quality Gate 17 条规则和 DSL 编译器的 44 个检查点。
>
> "后 3 个是 JD 要求的标准 AI 测试维度——**输出一致性**（同样需求多次生成，质量稳不稳定）、**需求鲁棒性**（需求描述有扰动，生成质量会不会断崖下跌）、**AI 幻觉检测**（有没有生成不存在的页面、元素、测试数据）。
>
> "评估器架构用的是策略模式，支持规则引擎、文本相似度、LLM-as-Judge 三种评估器可插拔。目前 MVP 用了前两种，LLM-as-Judge 接口已经预留好了。整个模块和我已有的 Quality Gate 形成分工——Gate 做 PASS/REJECT 的卡点决策，Evaluation Center 做 0-100 的精细度量和趋势分析。"
