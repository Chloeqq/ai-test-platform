## 一、现象

## 二、两层根因

### 根因 1：AI 测试点用「语义名」，页面对象用「真 testid」，词汇表对不上

AI 生成的测试点用 `involved_elements: [loginButton, navigationMenu, userInfo, ...]`（语义名），
而导入的页面对象元素是 `login-submit-btn / layout-sidebar-menu / ...`（前端真 testid）。
模糊匹配只接得住 `username`/`password` 这种 token 直配的，接不住语义跳跃的 → 阻断。

被阻断元素分三类：

| 类别 | 元素 | 真相 | 处理 |
|------|------|------|------|
| **A. 有 testid,只是名字不同** | navigationMenu→`layout-sidebar-menu`、userInfo→`layout-navbar-user-dropdown`、logoutButton→`layout-navbar-logout-item`、loginButton→`login-submit-btn`、loginPage→`login-page` | 元素都在 layout/login 页面对象里 | **加别名映射**（已做）✅ |
| **B. 真实存在但前端没打 testid** | `eyeIcon`（密码显隐，`<el-input show-password>` 内置渲染,无独立 testid） | 存在但导不出（testid 导出抓不到框架内置元素） | **待跟进**：页面对象新增元素 + CSS 相对定位 `[data-testid="login-password-input"] .el-input__password`，再加别名 `eyeIcon` |
| **C. 真不存在** | `rememberCheckbox`（记住我） | mall-admin 登录页源码无此元素 | **丢弃**这几条测试点 |

### 根因 2（更深）：别名映射功能在一次拆分重构中被回归损坏

## 四'、验证结果与绑定机制（2026-06-26 实测）

对 `preview-a48d7c5cc79e4d17.json` 的 29 个测试点跑真实绑定路径（`_page_object_generation_context` → `resolve_involved_element_codes`,任意 unknown 即 block）：**阻断 29→4**。

**关键机制（务必理解）**：
- 元素绑定是 **精确别名查表,无模糊匹配**（`element_binding.resolve_element_code` = `alias_map.get(key)`）。别名图由 `build_element_alias_map` 从每个元素的 `code / locator_value / element_name / aliases_json` 构建。
- 从前端导出的页面对象 `aliases_json` 为空、且用真 testid,而 AI 测试点用语义名（`username`/`loginButton`/...）→ **每个语义名都必须有对应别名,否则 unknown→block**。
- 绑定只看「**当前页**的 `_is_generation_qualified_element` 合格元素」（active + approved + stability∈{high,medium}）。**不加载 layout/其它页**。

**已修复（让 25/29 通过）**：
- 给 login 元素补语义别名:`username`→login-username-input、`password`→login-password-input、`loginButton`→login-submit-btn、`loginPage`→login-page、`eyeIcon`→login-password-toggle-btn。
- 把这些元素 `stability_level` 补为 `high`(原本为空 → 不合格 → 不进绑定上下文,这也是 B 类 eyeIcon 元素一开始没生效的原因)。

**剩余 4 条阻断及原因**：
| 测试点 | 缺元素 | 根因 | 处理 |
|--|--|--|--|
| intent-02 / intent-29 | userInfo, navigationMenu | 登录后**首页/布局**元素,在 `layout` 页对象里,但绑定只加载 `login` 单页 | **跨页绑定限制**(见 TODO) |
| intent-04 | logoutButton | 同上(在 layout) | 同上 |
| intent-28 | rememberCheckbox | mall-admin 登录页确无此功能 | 丢弃该测试点 |

→ 我之前加的 layout 别名(navigationMenu→layout-sidebar-menu 等)**映射本身正确,但因「单页绑定作用域」而不生效**。这 3 条「登录后验证」测试点天然跨 login→layout。

### 跨页绑定（已实现 2026-06-26）

平台原本已有**部分**跨页兜底：`_resolve_page_object_from_db` 里 `if page == "login"` 时跨页拉入 `home-page` 一个元素（`_load_cross_page_data_testid_element`,从 home/layout 查 testid）——**但只硬编码了 `home-page`**,覆盖不到 navigationMenu/userInfo/logoutButton（在 layout 外壳页）。

**实现**：在 `generate_pipeline_orchestrate._resolve_page_object_from_db` 末尾,加全局外壳页合并：
- 新增单一事实源常量 `_SHARED_SHELL_PAGE_CODES = ("layout",)`（admin 布局壳,登录后存在于所有业务页）。
- 解析任意非外壳页时,递归调 `_resolve_page_object_from_db(project, "layout")` 取其合格元素,`setdefault` 合并进当前页 mapping（主页面元素优先;外壳页自身不触发,无递归;外壳解析失败静默跳过）。
- 一处注入,覆盖 precheck（`resolve_page_object`）+ 实际生成两条路径。

**验证**（真实 `resolve_page_object("mall","login")` 路径,29 个测试点）：**阻断 4→1**。login 绑定上下文从 9 元素增至 23（含 8 个 layout 外壳元素）。仅剩 intent-28（rememberCheckbox,mall-admin 确无）。

**回归**：53 相关测试通过；唯一失败 `test_resolve_page_object_falls_back_to_yaml_assets` 与本次无关——是「清空页面对象」时删了 `assets/page-objects/web/*.yaml`(YAML 回退 fixture)所致,恢复 fixture 即通过。
