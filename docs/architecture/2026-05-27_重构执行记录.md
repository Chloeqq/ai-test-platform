### 3.2 改造方案

3 个 `workbench_state_store` 内部函数和 5 个公开函数增加可选 `db` 参数：

```python
# Before
def _upsert_db_item(path, item):
    with SessionLocal() as db:
        ...

# After
def _upsert_db_item(path, item, db=None):
    _owns_db = db is None
    if _owns_db:
        db = SessionLocal()
    try:
        ...
        if _owns_db:
            db.commit()
    finally:
        if _owns_db:
            db.close()
```

公开函数同步增加 `db` 参数并透传：
- `read_json_list(path, db=None)`
- `write_json_list(path, items, db=None)`
- `append_history(entry, db=None)`
- `append_runtime_run(entry, db=None)`
- `update_runtime_run(run_id, updates, db=None)`

### 3.3 facade 调用点更新

5 个 facade 方法中的 `store.append_history()` 调用从 `SessionLocal()` 改为传入 `db=db`：

| 方法 | 调用 |
|------|------|
| `batch_review_test_points` | `store.append_history({...}, db=db)` |
| `delete_workbench_test_cases` | `store.append_history({...}, db=db)` |
| `upsert_test_point_asset` | `store.append_history({...}, db=db)` |
| `delete_test_point_asset` | `store.append_history({...}, db=db)` |
| `rerun_case` | `store.append_history({...}, db=db)` |

### 3.4 保留的 SessionLocal 调用

以下 2 个场景因架构原因保留：

1. **`facade._execute_run` 闭包**（line 3271）：运行在子进程/线程中，请求的 `db` session 不可用，必须创建独立 session 持久化执行结果
2. **`generate_pipeline`（2 处）**：生成管线被 CLI 和 HTTP 双路径调用，当前没有统一的 `db` 参数传递链

### 3.5 事务规则

重构后的事务边界规则：

- **Router 层**：通过 `Depends(get_db)` 获取 session，请求结束时自动 commit/close
- **Facade 层**：接收 `db: Session`，透传给 service 和 store
- **Service/Repository 层**：接收 `db: Session`，绝不自己创建
- **Store 层**：接受可选 `db=None`，有则复用，无则创建独立 session
- **子进程/后台线程**：`SessionLocal()` 创建独立 session，负责自己的 commit/close

### 事务边界规则

- **Router 层**：通过 `Depends(get_db)` 获取 session，请求结束时自动 commit/close
- **Facade 层**：接收 `db: Session`，透传给 service 和 store
- **Service/Repository 层**：接收 `db: Session`，绝不自己创建
- **Store 层**：接受可选 `db=None`，有则复用，无则创建独立 session
- **子进程/后台线程**：`SessionLocal()` 创建独立 session，负责自己的 commit/close
