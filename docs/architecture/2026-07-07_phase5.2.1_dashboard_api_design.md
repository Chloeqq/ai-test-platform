## 2. API 设计

### 2.1 GET /api/workbench/quality/summary

返回项目质量概览。snapshot 聚合 + 实时 fallback。

### 2.2 GET /api/workbench/quality/ranking

返回 Asset 排名，score ASC（最低质量优先）。

### 2.3 GET /api/workbench/quality/issues

返回 5 个 count 按 asset 聚合的问题分布。

### 2.4 GET /api/workbench/quality/timeline/{asset_id}

返回单 asset 时间线，逐行计算 delta_score。

## 7. 实施前反方审计补充约束（2026-07-07）

### 7.1 架构边界

Dashboard 层职责：读取质量数据 / 聚合统计 / 趋势计算 / 查询展示。

禁止：修改 asset、生成 snapshot、调用 Gate、改 review 状态、重新计算质量规则。

Dashboard 是观察者，不是质量规则执行者。

### 7.2 Service 分层（防膨胀）

```python
quality_dashboard_service.py

├── snapshot reader
│   ├── _read_latest_snapshot(path)      # 读 JSONL 最后一行（reversed read）
│   └── _read_all_latest_snapshots(proj) # → {asset_id: snap}
│
├── asset fallback
│   └── _load_quality_with_fallback(proj, aid)  # snap or _build_quality_report
│
├── aggregation
│   ├── build_summary(project, db)
│   ├── build_ranking(project, limit)
│   └── build_issue_distribution(project)
│
└── timeline
    └── build_timeline(project, asset_id)
```

禁止 build_summary 内同时做文件读取 + 质量计算 + fallback + 排序。

### 7.3 Snapshot 读取

使用 reversed 读最后一行，避免大文件全量加载。Phase 6 可优化为 tail。

### 7.4 Fallback 边界

snapshot 存在 → 直接使用。snapshot 不存在 → 实时计算。
**不要**：snapshot 存在但字段缺失时静默 fallback。snapshot 是历史事实，异常应暴露。

### 7.5 Ranking Tiebreaker

```python
sorted(items, key=lambda x: (x["score"], x["asset_id"]))
```

保证 API 稳定性。

### 7.6 Issue 聚合

使用显式字段列表，不动态枚举 snapshot keys：

```python
ISSUE_FIELDS = [
    "zero_assertion_count", "candidate_step_count", "unprocessed_count",
    "quality_warning_count", "data_warning_count",
]
```

### 7.7 API 契约

summary/ranking/issues 返回 `generated_at` 字段（数据生成时间）。

### 7.8 测试补充

新增 Test 8：snapshot 中多个版本，验证 summary 使用最新版本（v3, not v1/v2）。

### 7.9 最终实施结论

**允许实施：YES**

范围：4 files, ~280 lines。
Dashboard = Read Only Domain
Snapshot = Historical Source
_build_quality_report = Fallback Only
Gate Rule = 不进入 Dashboard
