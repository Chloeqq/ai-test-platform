## 3. Approve Gate 规则设计

| # | 规则 | severity | 阻断 approve | 原因 |
|---|------|----------|-------------|------|
| 1 | `assertion_missing` 在 point.warnings | block | 是（已有） | 无断言=用例无效 |
| 2 | point.steps 无任何 `assert_` action | block | 是（新增） | 覆盖手工构造的零断言 DSL |
| 3 | `candidate_step` 在 steps 中 + 无 `assert_` action | block | 是（新增） | 未结构化=无法执行 |
| 4 | `candidate_step` 在 steps 中 + 有 `assert_` action | review | 否（允许） | 有断言但因含占位步骤需提示 |
| 5 | quality_warnings 非空 | review | 否（允许） | 提示性质，不阻断人工判断 |
| 6 | data_warnings | — | 否（允许） | 数据补全是正常人工操作 |

**与 Generate Gate 的差异**：

| 条件 | Generate Gate | Approve Gate |
|------|-------------|-------------|
| zero_assertion | block | block |
| unprocessed | block | block（= candidate_step + 无断言） |
| candidate_step + 有断言 | 不阻断 | 不阻断（提示） |
| quality_warning | 不阻断 | 不阻断 |
| data_warning | 不阻断 | 不阻断 |

Generate 和 Approve 规则一致。Approve 是人工防线，Generate 是机器防线。两道防线用同一标准，确保人工 approve 后机器也不会阻断。

```
if next_status == "approved":
    psteps = point.get("steps", [])
    pactions = [str(s.get("action", "")) for s in psteps]
    has_assertion = any(a.startswith("assert_") for a in pactions)
    has_candidate = "candidate_step" in pactions

    # Rule 1: assertion_missing in warnings (existing)
    point_warnings = point.get("warnings", [])
    if any("assertion_missing" in str(w) for w in point_warnings):
        raise HTTPException(422, detail={"code": "gate_reject_blocked", ...})

    # Rule 2: candidate_step + no assertion = unprocessed (new)
    if has_candidate and not has_assertion:
        raise HTTPException(422, detail={"code": "gate_reject_blocked", ...})

    # Rule 3: no candidate_step + no assertion = zero_assertion (new)
    if not has_candidate and not has_assertion:
        raise HTTPException(422, detail={"code": "gate_reject_blocked", ...})
```
