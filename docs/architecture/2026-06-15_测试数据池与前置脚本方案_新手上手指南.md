## 第二步：实现 DataPoolResolver（1 小时）

**要改的文件**: `apps/web-ui-service/app/services/test_data_pool_service.py`

**为什么**: 需要一个小函数：给一个 pool 名字和过滤条件，返回匹配的那个 item 的数据。

**怎么改**:

在文件末尾加这个函数：

```python
def resolve_pool_value(pool_name: str, filters: dict[str, str]) -> dict[str, str]:
    """从数据池中按标签过滤，返回第一个匹配 item 的 value 字典。
    
    例如: resolve_pool_value("login_accounts", {"status": "locked"})
          → {"username": "locked_user", "password": "test123"}
    """
    from app.core.database import SessionLocal
    from app.repositories.test_data_pool_repository import TestDataPoolRepository
    
    db = SessionLocal()
    try:
        repo = TestDataPoolRepository(db)
        pool = repo.get_by_name(pool_name)
        if pool is None:
            return {}
        items = repo.list_items_by_pool(pool.id)
        for item in items:
            item_tags = getattr(item, 'tags', {}) or {}
            # 检查所有 filter 条件是否匹配
            if all(
                str(item_tags.get(k, '')).strip() == str(v).strip()
                for k, v in filters.items()
            ):
                return {
                    "username": str(getattr(item, 'item_key', '')).strip(),
                    "password": str(getattr(item, 'item_value', '')).strip(),
                }
        return {}
    finally:
        db.close()
```

**验证**: 先通过前端往 `login_accounts` 数据池里加一个 item，tags 填 `{"status": "locked"}`。然后在 Python 里测试：

```python
from app.services.test_data_pool_service import resolve_pool_value
result = resolve_pool_value("login_accounts", {"status": "locked"})
print(result)  # 应该输出你填的 username 和 password
```

## 第三步：让生成管线支持 source_type: pool（2 小时）

**要改的文件**: `generate_pipeline_format.py`

**为什么**: 目前管线只处理 `source_type: inline`（硬编码值）。需要让它认识 `source_type: pool` 并从数据池取数据。

**怎么改**:

找到 `_enrich_dsl_v1_1_data_bindings` 函数（大约在 1125 行）。在函数里找到处理 `data` 字段的循环。添加对 `source_type: pool` 的处理：

```python
# 在 _enrich_dsl_v1_1_data_bindings 函数里，处理每个 data 字段时：

for key, raw_entry in data.items():
    source_type = str(raw_entry.get("source_type", "inline")).strip().lower()
    
    if source_type == "pool":
        # 1. 从数据池解析值
        pool_name = str(raw_entry.get("pool_name", "")).strip()
        filters = raw_entry.get("filter", {}) if isinstance(raw_entry.get("filter"), dict) else {}
        
        from app.services.test_data_pool_service import resolve_pool_value
        pool_data = resolve_pool_value(pool_name, filters)
        
        # 2. 把解析到的值写入 data 的 value
        for k, v in pool_data.items():
            if k in data:
                data[k]["value"] = v
                data[k]["source_type"] = "inline"  # 解析后变成 inline
                data[k]["_resolved_from_pool"] = True
```

**为什么这样写**: 
- 在**生成时**解析 pool，而不是执行时。这样 YAML 里写的是解析后的值，执行时不需要额外查 DB。
- `_resolved_from_pool` 标记让以后知道这个值是从 pool 来的，方便调试。

**验证**: 创建用例 0021 时把 data 改成引用 pool（通过 API 传 `source_type: pool`），看生成的 YAML 是否正确取到了 `disabled_user` 的 username 和 password。

## 第四步：让 AI 生成 candidate 时输出 source_type: pool（1 小时）

**要改的文件**: `orchestrator_service.py` 或 AI prompt 模板

**为什么**: AI 目前生成 candidate 时，data 字段全是 inline。需要让 AI 知道"当需要锁定账号时，应该引用数据池"。

**怎么改**（最简单的方式——改 prompt）：

在 orchestrator 的 system prompt 里加一段：

```
## 测试数据规则

当测试场景涉及特定账号状态（锁定、禁用、VIP等）时，不要编造 username/password。
而是使用数据池引用：

正确写法:
  "data": {
    "username": {"source_type": "pool", "pool_name": "login_accounts", "filter": {"status": "locked"}},
    "password": {"source_type": "pool", "pool_name": "login_accounts", "filter": {"status": "locked"}}
  }

可用的数据池: login_accounts
可用状态标签: active, locked, disabled

只有当账号状态为"正常/active"时，才可以用 inline 值。
```

**为什么用 prompt 而不是改代码**: 改 prompt 最快。以后数据池多了，再加结构化的 pool catalog API。

> ⚠️ **运行时实际约定（以此为准）**
>
> 上面 `filter: {"status": "locked"}` 是早期设计稿。**当前 Runner 的解析器
> （`runners/web-playwright-python/runner/data_expander.py` 的 `_resolve_pool_value`）
> 只支持 `pool_name` + `key` 精确匹配，不支持 `filter`。** 生成管线的自动路由
> （`route_identity_data_to_pool`）按以下零硬编码约定改写身份数据：
>
> - **池名** = 页面名 `{page}`（如 `login`、`order`；page 为空时退回 `login`）
> - **item key** = `{字段名}_{状态}`（如 `username_locked`、`password_disabled`）
>
> 因此在 Web UI 里要创建的池是 **`login`**，并加入这些 item：
> `username_locked` / `password_locked` / `username_disabled` / `password_disabled`，
> 各自的 `value` 填对应账号的实际用户名/密码。状态关键词来自 precondition
> （“锁定/locked” → `locked`，“禁用/disabled” → `disabled`）或结构化
> `account_state.state`。

## 常见踩坑指南

| 问题 | 解决 |
|------|------|
| Alembic migration 报 multiple heads | `alembic heads` → `alembic merge` |
| `resolve_pool_value` 返回空 | 检查 tags 字段是否为 JSON、filter 的 key/value 是否精确匹配 |
| 数据池 item 加不了 tags | 确认 migration 已执行，Model 里加了 `tags` 字段 |
| prompt 改了但不生效 | 重启 orchestrator 容器 |
